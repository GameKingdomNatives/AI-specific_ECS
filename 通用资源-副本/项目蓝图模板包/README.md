# 项目蓝图模板包（不依赖特定文件）

> 本目录把《项目规划蓝图》的资源提炼为**通用项目蓝图模板**——剥离具体项目内容（如"心智编程"的身份/边界/状态条目），保留**文档结构与通用管理规则**，供新项目 / 重新规划时套用。
> 来源：`项目规划蓝图/`（项目身份 / 边界约束 / 当前状态）；本包为通用模板，**不依赖特定文件或具体项目内容**。

## 包定位

项目蓝图的"三件套"（身份 / 边界 / 状态）定义项目从"是什么、为什么做、不能变成什么样、做到哪了"到**可持续迭代**的完整骨架。本包给出每份文档的**通用结构 + 填写指引 + 维护约定**，填入项目自身信息即可复用。

## 文件清单

| 文件 | 内容 | 提炼来源 |
|------|------|----------|
| `项目身份模板.md` | 定义项目是什么 / 为什么存在 / 传递什么感受——核心定位 / 价值词 / 差异化 / 核心原则 / 环境硬约束 / 背景前提 / 变更记录 | `项目规划蓝图/项目身份.md` |
| `边界约束模板.md` | 定义项目不能变成什么——设计反模式 / 技术红线 / 调性约束 / 禁止操作 / 变更记录 | `项目规划蓝图/边界约束.md` |
| `当前状态模板.md` | 记录实际进度（只记事实不记计划）——项目概况 / 已完成工作 / 架构地图 / 决策记录 / 已知问题 / 远期目标 / 更新记录 | `项目规划蓝图/当前状态.md` |

> 模板中 `{{占位说明}}` 为待填项；**通用管理规则**（如"约束只增不减""事实只记不计划""时间戳铁律""价值词需可验证"）已作为模板约定保留，可直接复用。

## 使用方式

1. **初始化新项目**：复制三份模板 → 填入项目身份 → 补边界 → 从空状态开始迭代（配合"开发提示词包"中的迭代协议/工作流）。
2. **套用顺序**：先 `项目身份模板`（定方向）→ `边界约束模板`（划红线）→ `当前状态模板`（记事实）。三者配合，方向>约束>事实。
3. **文档间关系**：`项目身份`（方向层）/ `边界约束`（护栏层）/ `当前状态`（事实层）——迭代开发时三者同步更新（身份变更→身份+变更记录；边界变更→边界+变更记录；每次迭代→当前状态+更新记录）。

## 通用约定（模板包内置，可直接复用）

- **身份**：价值词必须是"可验证的主观体验"（非功能描述）；核心原则必须排序（冲突时高优先级胜出）；一句话若也能描述其他项目则不够精准。
- **边界**：约束分三层（设计反模式 / 技术红线 / 调性约束）；**约束只增不减**（删除需走方向校正并记录原因）；每条必须有清晰"越线信号"（"看起来有点像"不算）；禁止操作必须具体到可执行。
- **状态**：**只记录事实，不记录计划**（"打算做"不写这里）；迭代完成后更新、里程碑即时更新；无问题时保留空表头不删；决策记录解释"为什么这么选"。
- **时间戳铁律**：每份模板文档标题区标注 `> 最后更新：YYYY-MM-DD`，每次修订同步时间戳（文档新鲜度的唯一信号）。
- **与开发规则配合**：模板填入后，按"开发提示词包"中的《AI执行规则·启动流程》读取（状态→身份→边界→灵感池→上次迭代）与《迭代执行协议》推进开发。
