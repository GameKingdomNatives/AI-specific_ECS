# 项目身份

## 一句话

**一个容器、两个平级项目**：`agent-specific_ecs` 是可被外部消费的 ECS 引擎；`深入战火` 是在它之上推进的俯视角机甲弹幕射击游戏。测试夹具 `@itb/fixture` 只是替身。

## 定位

- **引擎**：agent 原生、工具无关的自描述能力内核。任何能读写代码、执行命令的 agent 都能直接消费；不绑定 IDE、SDK 或 MCP。
- **游戏**：验证「攻防共享辐能池 + 战中零指挥 + 僚机自主协作」的可玩形态；用游戏的真实需求反哺引擎。
- **工程内核**：门禁、契约、回执、stamp、分支保护、迭代流程——质量靠机器可读证据，不靠散文。

## 设计支柱

1. **单一认知模型**：玩家只驾驶旗舰；指挥决策前置到战前配置。
2. **攻防共享资源池**：开火与开盾共用辐能；硬/软辐能区分强制出节奏。
3. **可读的协作**：僚机行为必须可预期、可理解，否则军团感崩塌。
4. **证据优先**：每条规则有 guide / sensor / negativeTest；L3 不计 PASS。
5. **产品与内核分离**：引擎包体不含游戏内容；游戏不私改引擎契约。

## 感觉词

- 引擎：**可信、可查、可拒**（可回放、可审计、可拦截）。
- 游戏：**紧张但可控、每局都有新的辐能管理发现、不是一个人在战斗**。

## 非目标

- 不做生产级承诺（原型；npm 首包后仍是 0.x）。
- 不做联机 / 移动端 / 桌面打包 / mod 加载器（本轮）。
- 不把游戏内容写进引擎源码或包体。
- 不追求美术；先纯色块可读。
