# 文档与记忆规范

## 1. 单一事实

| 内容 | 唯一来源 |
|---|---|
| 方向 / 支柱 | `工程文档/项目身份/项目身份.md` |
| 可执行边界 | `AGENTS.md` |
| 流程 | `docs/workflow/` |
| 详细状态 / 交接 | `docs/handoff.md` |
| 决策理由 | `docs/adr/` |
| 机器契约 | `contracts/` |
| 系统职责 | `docs/systems/` |

同一事实只写一处；其他地方引用路径，不复制正文。

## 2. 更新时机

- 功能完成 → 系统卡 + 当前状态 + 变更记录（与代码同提交）。
- 迭代结束 → 迭代记录、质量日志、交接。
- 新约束 → AGENTS + 边界约束。
- 新想法 → 灵感池（AI 不自行采纳）。

## 3. 命名与语言

- 目录与文件名用中文语义（项目身份 / 迭代记录 / 灵感池），命令与代码用英文。
- 公开产物（npm / GitHub）尽量中英双语；不能双语时英语优先。

## 4. 交接

每次会话结束更新 `docs/handoff.md` 顶部与 `工程文档/交接/交接清单.md`；新会话先读交接，不凭记忆开工。

## 5. 术语

缩略名词在同一份输出中首次出现时给全称与来源路径（人 2026-10-11 约定），之后才可用简称。

## 6. 记忆

- 热记忆只写"新事实 / 人的纠正 / 稳定环境事实"；不复述检索结果。
- 跨会话结论写进仓库文档，不依赖记忆。
