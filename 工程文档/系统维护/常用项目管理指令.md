# 常用项目管理指令（速查）

> 这是**命令速查表**，不是规格书。规则正文在 `AGENTS.md` 与 `docs/workflow/完整工作流.md`；本文件只回答「想做 X，敲哪条」。
> 指令文件在哪、什么时候读：见同目录 `项目管理指令索引.md`。

## 三条铁律

1. **开工先看状态**：`node tools/status.mjs`（HEAD / 脏文件 / 上次门禁 / 环境）。
2. **门禁不过不提交、不推送、不声称完成**；没跑过门禁就说完成 = 未交付。
3. **文档与代码同提交**；同一事实只写一处正文，别处只放摘要与指针。

## 开工

```bash
node tools/status.mjs                 # 一屏：HEAD、分支、脏文件、上次门禁、环境指纹
node tools/gate.mjs --fast            # 快速门禁（不含依赖边界与 git 事实）
```

首读顺序（细则见 `AGENTS.md` 开工首读）：状态 → 当前状态.md → docs/交接.md 顶部 → 项目身份 → 迭代流程 → 最后一个迭代记录。

## 日常循环

```bash
npm run typecheck                      # 等价：node node_modules/typescript/bin/tsc -b
node tools/gate.mjs --fast             # 改完一个模块就跑，别攒到最后
node tools/gate.mjs                    # 收尾全量：tsc + eslint + 自定义校验 + 测试 + git 事实 + 依赖边界
```

- 门禁结论看**报告本身**，不看退出码：`artifacts/gate/<run>/report.md`。
- 本机沙箱里 `build` / `storybook` / `starter` 属于 **L3 环境受限**（禁止管道子进程），**不计 PASS**；三项以外全绿才算机器侧干净。

## 测试

```bash
node tools/gate.mjs --fast             # 测试统一由门禁跑；沙箱里直接 node --test 会 spawn EPERM
node apps/game/tests/replay-frames.test.ts   # 单文件在可用环境下可直接跑（internal node:test 自执行）
```

测试基线：`tools/test-baseline.json`（`minTestFiles` 只增不减）。新增测试文件时基线要一起改（保护路径，需在提交信息里注明）。

## 交付与分支

```bash
node tools/flow.mjs status             # 当前分支策略与待清理分支
node tools/flow.mjs sweep              # 清理已合并分支（--remote 清远端）
node tools/flow.mjs ship               # 交付：门禁 + receipt + 深检 + 合并 + 推送 + 清理
node tools/push.mjs                    # 推送前体检（网络通道、stamp）
node tools/receipt.mjs                 # 回执：把证据写成机器可读记录
```

推送通道问题（443 被重置等）见 `docs/runbooks/04-推送与网络策略.md`；分支生命周期见 `docs/runbooks/05-分支生命周期.md`。

## 面板、回放与调试入口

```bash
npm run dev                            # 本地游戏（Vite，apps/game，端口 5173）
                                       # http://localhost:5173/                      → 游戏场景 flux-core（默认）
                                       # http://localhost:5173/?scene=demo.scene.json → 引擎夹具场景（只在对照引擎能力时用）
                                       # ?scene= 可省 .scene.json 后缀；写错才回退默认
                                       # 页面底部 HUD 会打印 `scene <名字>`：不是 flux-core 就说明场景没装起来npm run panel                          # 治理面板：先 collect 再 open
npm run replay                         # 离线回放工具
npm run review                         # 审查报告
npm run drill                          # 故障演练
npm run deep                           # 深检（每 5 次提交一次；--dry-run 先看）
npm run bench                          # 性能基线对比
```

游戏内调试：`?debug` 打开调试视图；`R` 打开复盘面板；`?capture` 用于截图/确定性捕获。

## 常见故障与判定

| 现象 | 判定与处理 |
|---|---|
| `spawn EPERM` / `couldn't create signal pipe` | 本机沙箱禁止管道子进程。改用门禁跑测试与检查；提交时在全量门禁已跑的前提下用 `git commit -n`，并在提交信息里写门禁 run id 与 L3 项 |
| 门禁 `build` / `storybook` / `starter` 失败 | 先确认是不是 L3 环境受限；是则记录，不得当 PASS，也不得当代码违规 |
| 改了 `tools/` / `tsconfig*` / `package.json` 被拦 | 保护路径。确需改动：`ALLOW_PROTECTED=1 node tools/gate.mjs`，并在 `docs/adr/` 补记录 |
| 依赖方向报错 | 看 `tools/checks/depcruise.mjs` 输出；引擎不得 import `apps/`，`core` 不得 import `ports` |
| 文档校验失败 | `docs-map` 查结构与旧路径引用；按报告里点名的文件改 |

## 维护

- 命令或流程变了，**先改规则正文**（`docs/workflow/`），再回来同步这张表；不要反向制造平行真相。
- 新增常用指令时，同时更新 `项目管理指令索引.md` 的「信源」表。
