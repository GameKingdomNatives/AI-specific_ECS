# 项目管理指令索引（信源目录）

> 目的：任何人（或新会话）都能在一屏内知道**哪份文件管什么、什么时候必须读**，不必凭记忆找规则。
> 命令速查在 `常用项目管理指令.md`；本文件只做索引，不复制规则正文。

## 信源表

| 信源 | 路径 | 管什么 | 什么时候读 |
|---|---|---|---|
| 项目宪法 | `AGENTS.md` | 结构、边界、权限、门禁、保护路径、环境事实 | **每轮开工必读** |
| 最终指令 | `docs/00-最终指令.md` | 规格总纲；与 AGENTS 冲突时以它为准 | 规则打架时 |
| 工程文档入口 | `工程文档/索引.md` | 工程事实目录与单一事实规则 | 找工程事实前 |
| 项目身份 | `工程文档/项目身份/项目身份.md` | 定位、设计支柱、感觉词、非目标 | 判断「该不该做」时 |
| 当前状态 | `工程文档/当前状态.md` | 一屏状态摘要 | 开工第二步 |
| 边界约束 | `工程文档/边界约束.md` | 10 条边界与 HARD 清单的解释（可执行版在 AGENTS） | 要动边界时 |
| 完整工作流 | `docs/workflow/完整工作流.md` | 从立项到发布怎么操作 | 第一次做某个流程时 |
| 迭代流程 | `docs/workflow/迭代流程.md` | 单轮迭代节奏、证据分层 L0–L4、人的在场规则 | **每轮迭代必读** |
| 工作流索引 | `docs/workflow/索引.md` | 流程文件目录 | 找流程时 |

## 优先级（冲突时）

1. 人的当场指示。
2. `docs/00-最终指令.md`（规格总纲）。
3. `AGENTS.md`（可执行约束、权限、保护路径）。
4. 本索引列出的其余文件（各管一段，不互相覆盖）。

## 维护约定

- 新增一份规则/流程文件：**必须**在本表加一行（来源、管什么、何时读），否则新会话找不到它。
- 规则正文只存在一处；本表与 `常用项目管理指令.md` 都是指针，不复制正文。
