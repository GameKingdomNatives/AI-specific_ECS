# IDEA-003 · 常态化审计服务器

- 级别：P2
- 状态：待裁定
- 提出：2026-10-29（人提问「能不能提供 npm run <占位符> 形式的本地服务器启动命令来执行常态化审计」，明确说不要求现在做）

## 想法

现在门禁与审计是**一次性命令**：`node tools/gate.mjs`、`node tools/deep-audit.mjs`、`node tools/status.mjs`，跑完看 `artifacts/gate/<run>/report.md`。人要看「这两天哪些项在变红」「某文件最近几次门禁都红」只能翻目录。

提案：加一个只跑在地上的本地服务，用一条命令起来，浏览器里点按钮触发固定检查、直接看趋势。

## 形态（最小）

| 项 | 提案 |
|---|---|
| 启动命令 | `npm run audit:serve`（占位名，也可叫 `gate:serve`） |
| 实现 | `tools/audit-server.mjs`，只用 `node:http`，**不引第三方依赖** |
| 监听 | 固定 `127.0.0.1:<port>`，默认 7717；不绑 0.0.0.0 |
| 能触发什么 | **固定白名单**：`tsc`、`test:<name>`、`gate --fast`、`registry`、`eslint`；**不做任意 shell、不收用户输入命令** |
| 数据源 | 只读 `artifacts/gate/*/report.json`；页面出每次 run 的通过/失败矩阵与趋势 |
| 写操作 | 除「触发一次检查」外不写仓库；报告仍由 gate 自己落盘 |
| 安全 | 仅本机、无认证但不可远程访问；POST 带一次性 nonce 防跨站误触发 |

## 与现有工具的关系

- 不替代 `tools/gate.mjs`：服务只**调用**它，判定口径只有之一。
- 不替代 CI/夜检：那是「没人时自动跑」，这个是「有人在时按需看」。
- 与 `tools/panel/`（治理面板）区别：面板是静态汇总快照，服务是**可触发 + 实时**。

## 不做的事

- 不做万能命令执行器（等于把 shell 暴露给浏览器）。
- 不做远程访问与账号体系（个人项目，本地足矣）。
- 不在服务内重写检查逻辑（否则出现第二套判定 = 平行真相）。
