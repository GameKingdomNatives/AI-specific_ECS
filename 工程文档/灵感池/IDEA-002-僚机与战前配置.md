# IDEA-002 · 僚机与战前配置

- 级别：P1
- 状态：待裁定
- 提出：2026-10-28（AI 依据项目身份的支柱 1 与支柱 3 提出，待人裁定）

## 想法

项目身份写的核心体验是「玩家只驾驶旗舰、指挥决策前置到战前配置」，感觉词里有「不是一个人在战斗 / 可读的协作」。
但当前游戏里**没有僚机，也没有战前配置**：一局只有一个玩家实体，全部决策都在战中靠按键完成。
也就是说：**计划清单上的三件事（三武器槽 / 标准组件上移 / 战后复盘）都做完了，但项目身份里最核心的那条承诺还没被验证过。**

## 可选形态

| 形态 | 内容 | 与支柱的关系 |
|---|---|---|
| A · 僚机（推荐先做） | 1 架 AI 僚机：跟随、自主交战、避让玩家火线、辐能同样会过载；机甲上方一行状态（跟随 / 交战 / 排散 / 无目标） | 支柱 1（只驾驶旗舰）+ 支柱 3（可读的协作） |
| B · 战前配置 | 开打前选三槽装填取舍 + 僚机行为偏好（激进 / 保守），战前一次决定、战中不改 | 支柱 1（指挥前置）；与 A 互补 |
| C · 战中指令 | 战中按一个键给僚机下「集结 / 突击 / 护盾」 | **与支柱 1 冲突**（战中零指挥），采用前需人先改支柱 |

## 对齐检查

- [x] 服务核心循环（3 分钟一局里多一个可读的协作者，辐能取舍从「我一个人」变成「我们俩」）
- [x] 强化至少一个感觉词（「不是一个人在战斗」「可读的协作」）
- [x] 不与设计支柱冲突（A、B 符合；C 冲突，需人改支柱）
- [x] 不违反边界约束（僚机是游戏系统，不进引擎包体；回放/事件层已能承载僚机行为）

## 验证方式

最小验证：只加 1 架僚机，一局 3 分钟 × 2 轮，看三件事——

1. **可读**：中途问自己「僚机现在在干什么、下一步会干什么」，能不能立刻答上来（答不上就是失败，不是数值问题）。
2. **不抢戏**：玩家是否仍然觉得自己是主角（僚机不能替玩家解决火力问题）。
3. **辐能更复杂还是更混乱**：僚机也吃辐能后，玩家对「谁该省、谁该打」的判断是否更清楚而不是更乱。

复盘面板已能记录僚机（帧 + 事件层不需要改），验证时直接回放看「它当时跟没跟上、有没有挡线」。
