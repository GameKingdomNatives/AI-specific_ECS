# 四天学习路径（每天 30–45 分钟，全部可动手）

目标：不是「会打开 Storybook」，而是「能把一个界面拆成组件与状态，并导出静态网页交付」。

## Day 1 · 认识 story 与 args

要理解：**story 是状态快照，args 是传给组件的输入。**

练习：

1. 打开 `src/components/Button.stories.tsx`，把「默认」的 `label` 改成「取消」，保存，看页面变化；
2. 新增一个 story，测试长文案：

   ```tsx
   export const 长文案: Story = { args: { label: '导出当前这一页的完整数据文件' } };
   ```

3. 在 Controls 面板里开关 `disabled`，观察按钮。

验收：能解释「为什么一个组件要写多个 story，而不是一个示例页」。

## Day 2 · 让参数可调（argTypes / parameters / decorators）

要理解：Controls 由 `argTypes` 驱动；全局外观由 `decorators`、`parameters` 控制。

练习：

1. 给「状态文字」的 `tone` 加 `argTypes`（三选一）；
2. 打开 `.storybook/preview.ts`，把背景改成 `#0b0b0b`，观察所有 story；
3. 给某一个 story 单独加 `parameters` 覆盖背景。

验收：能说清「全局默认」与「单个 story 覆盖」谁优先。

## Day 3 · 补边界状态与可读性

要理解：设计稿通常只画「正常、有数据」的样子；实现必须处理空、错、禁用、长文案。

练习：

1. 打开「信息行」的「空数据」story，确认显示「暂无数据」；
2. 给按钮加一个只有图标的样子，检查它有没有可读的名称（浏览器 DevTools → Accessibility）；
3. 检查对比度：弱化文字在深色背景上是否达到 4.5:1。

验收：每个组件至少三类状态：默认 / 边界（空或错误）/ 禁用。

## Day 4 · 构建与交付

要理解：静态构建就是交付物。

练习：

1. `npm run build`，找到 `storybook-static/`；
2. `npm run serve`，打开 `http://localhost:7007`；
3. 把 `storybook-static/` 压缩成 zip；
4. 让另一个人（或另一个浏览器）打开，确认不需要安装任何东西。

验收：能独立完成「构建 → 发 zip → 对方打开」。

## 进阶（可选，按需安装）

- `@storybook/addon-a11y`：在面板里直接看可访问性问题；
- `@storybook/test`：用 `play` 函数模拟点击、输入，把交互写成自动检查；
- `@storybook/addon-docs`：给组件生成文档页。

先把四天路径跑完，再考虑这些。
