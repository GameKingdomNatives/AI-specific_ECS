# 四天学习路径（每天 30–45 分钟，全部可动手）

目标不是「会开 Storybook」，而是「能把一个设计稿拆成组件与状态故事，并交付静态包」。

## Day 1 · story 与 args

要理解：story 是状态快照；args 是可变输入。

练习：

1. 打开 `src/components/Button.stories.tsx`，把 `默认` 的 `label` 改成「读档」，保存，观察页面；
2. 新增一个 story：

   ```tsx
   export const 长文案: Story = { args: { label: '导出当前这一局的完整录制文件' } };
   ```

3. 在 Storybook 的 Controls 面板改 `disabled`，看按钮如何变化。

验收：能解释「为什么一个组件需要多个 story，而不是一个示例页」。

## Day 2 · argTypes、decorators、parameters

要理解：Controls 由 `argTypes` 驱动；全局外观由 `decorators`/`parameters` 控制。

练习：

1. 给 `StatusNote` 的 `tone` 加 `argTypes`（inline-radio：info/muted/error）；
2. 在 `.storybook/preview.ts` 里把背景改成 `#0b0b0b`，观察所有故事；
3. 给某个 story 单独加 `parameters: { backgrounds: { default: 'canvas' } }` 覆盖全局。

验收：能说清「全局默认」与「单个 story 覆盖」的优先级。

## Day 3 · 空状态、错误态与可访问性

要理解：设计稿通常只画「有数据、正常」的样子，而实现必须处理空与错。

练习：

1. 打开 `StatRow.stories.tsx` 的 `空状态`，确认它渲染「暂无数据」；
2. 给 `Button` 加一个 `aria-label` 场景（图标按钮），用浏览器 DevTools 检查可访问名称；
3. 检查颜色对比度：`stone-500` 在 `#111` 上是否达到 4.5:1（可用 DevTools 的对比度检查）。

验收：每个组件至少有「默认 / 空或错误 / 禁用」三类状态。

## Day 4 · 构建与交付

要理解：Storybook 的静态产物就是交付物。

练习：

1. `npm run build`，看 `storybook-static/` 生成；
2. `npm run serve`，打开 `http://localhost:7007`；
3. 把 `storybook-static/` 压缩成 zip；
4. 让另一个人（或另一个浏览器）打开，确认不需要任何安装。

验收：能独立完成「构建 → 发 zip → 对方打开」这条链路。

## 进阶（可选，按需安装）

- `@storybook/addon-a11y`：面板里直接看可访问性问题；
- `@storybook/test`：用 `play` 函数模拟点击、输入，把交互写成自动化检查；
- `@storybook/addon-docs`：给组件生成文档页（MDX）。

这些都不是起步必需；先把四天路径跑完。
