# Storybook 与 Figma：区别、对应关系与工作方式

> 本文中的「设计方」指**未来可能的协作方**；当前是个人项目，没有常态设计参与。这套对照用于未来合作时快速对齐认知。

## 1. 一句话区别

- **Figma**：画「设计应该长什么样」，是**设计源文件**，不产出可运行代码。
- **Storybook**：展示「组件实际长什么样」，是**真实代码的状态目录**，能被交付、被测试、被版本管理。

两者不是替代关系。Figma 免费版可以继续用来画草图；**验收以 Storybook 为准**。

## 2. 对比

| 维度 | Figma | Storybook |
|---|---|---|
| 产物 | 设计文件（云端/本地文件） | 可运行的 React 组件 + 静态站点 |
| 是否可运行 | 否（原型是模拟） | 是（真实渲染） |
| 是否进版本库 | 一般不进 | 进（`*.stories.tsx`） |
| 设计师需要装什么 | 浏览器 | 浏览器（看静态包） |
| 费用 | 免费版可用；Dev Mode 等需付费 | MIT，免费商用 |
| 能改代码吗 | 不能（Dev Mode 只是标注/上下文） | 不能（它展示代码） |
| 适合做什么 | 探索布局、视觉、交互流程 | 固化状态、验收、回归、交付 |
| 不适合做什么 | 精确到像素的最终实现、状态覆盖 | 自由探索、视觉发散 |

## 3. 概念对应表（从 Figma 迁移时按这张表翻译）

| Figma 里的东西 | Storybook 里的对应物 |
|---|---|
| 组件（Component） | `src/components/Xxx.tsx` |
| 组件变体（Variant） | story 或 `args`（如 `tone: 'primary'`） |
| 组件属性（Properties） | props + `argTypes`（Controls 面板） |
| 页面/画板（Frame） | 一个 story（或组合 story） |
| 设计 token（颜色/字号/间距） | `src/tokens.ts` + Tailwind 类 |
| Prototype 的交互 | `play` 函数（需装测试插件）或人工评审 |
| 设计标注/切图 | story + 静态包（直接看实现） |
| 版本历史 | git 提交历史 |

## 4. 工作方式怎么变

**以前**：设计在 Figma 画完 → 开发照着写 → 设计发现不一致 → 再改。

**现在**：

1. 设计仍可用 Figma 画稿（免费版足够），交付时给出「组件名 + 状态 + 期望值」；
2. 开发在 `src/components/` 实现，并为每个状态写 story；
3. 双方打开 Storybook（本地 `:6006` 或静态包 `:7007`）对照；
4. 差异按「哪里、期望、为什么」提，开发改组件与 story；
5. 静态包重新构建，作为这一轮的验收物。

好处：讨论对象从「一张图」变成「真实组件 + 明确状态」，不会出现「你看到的是设计稿，我看到的是实现」的错位。

## 5. 什么不能从 Figma 直接搬

- **战场画面**（Pixi canvas 里的单位、弹道、特效）不在 DOM 里，Storybook 不覆盖；
- 复杂的拖拽/画布交互：Storybook 能展示但不易模拟，需另写交互测试；
- 像素级动画曲线：以代码为准，Figma 只给参考；
- 设计稿里的「假数据」：story 里要用真实结构的假数据，并显式给空状态/错误状态。

## 6. 成本对照

| 项 | Figma 路线（Dev Mode） | 本方案（Storybook） |
|---|---|---|
| 设计方费用 | 需付费席位 | 0 |
| 是否离线 | 否（云端） | 是 |
| 产物能否直接用 | 否 | 是（静态站点 + 组件） |
| 持续依赖 | Figma 账号与订阅 | 无 |

结论：**Figma 当草稿本，Storybook 当验收台。**
