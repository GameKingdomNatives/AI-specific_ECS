# 从设计稿迁移到 Storybook：七步

适用于「已经有一版设计稿，需要落成组件与状态」的情况。

## 第 1 步：盘点组件

把设计稿里的元素归类，只保留**会重复出现**的：按钮、状态文字、信息行、面板、列表、输入框。一次性的装饰不要组件化。

产出：一张组件清单（名称 + 用途 + 状态）。

## 第 2 步：盘点状态

对每个组件列状态：默认、鼠标悬停、键盘聚焦、禁用、空数据、错误、长文案。设计稿没画的，按实现补。

产出：组件 × 状态的表格。

## 第 3 步：抽取颜色与尺寸

把设计稿里的颜色、字号、间距、圆角写进 `src/tokens.ts`；能对应 Tailwind 类的优先用类（如 `stone-900`）。

规则：一个值只出现一次；组件里不写魔法数字。

## 第 4 步：先做一个组件 + 三个 story

选最简单的按钮开始。组件只接收参数，不写业务逻辑。

验收：Storybook 里能看到三种状态，Controls 能改参数。

## 第 5 步：按表格补故事

每个状态写一个 story；差异用 `args` 表达，不要复制组件。

## 第 6 步：对照评审

构建静态包 → 打开 → 按「哪里、期望、为什么」提差异 → 改组件与 story。

## 第 7 步：固化

- story 与组件一起进版本库；
- 在持续集成里加一条 `storybook build`；
- 每次界面改动都更新静态包。

## 不能直接迁移的部分

| 设计稿内容 | 处理 |
|---|---|
| 画布类内容（地图、图表、游戏画面） | 不迁；由对应渲染层负责 |
| 复杂交互（拖拽、画布） | 写成交互测试或人工验收 |
| 像素级动效 | 以代码为准，设计稿仅参考 |
| 占位文案 | 换成真实结构的假数据，并补空状态 |

## 检查点

- [ ] 每个组件至少三态：默认 / 边界 / 禁用
- [ ] 颜色与尺寸只来自 tokens 与 Tailwind 类
- [ ] 组件不引用业务代码
- [ ] 静态包能离线打开
- [ ] 有一次真实渲染的对照确认
