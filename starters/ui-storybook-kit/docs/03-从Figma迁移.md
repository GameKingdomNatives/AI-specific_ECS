# 从 Figma 稿迁移到 Storybook：七步

适用于「已经有一版 Figma 设计，需要落成组件与故事」的情况。

## 第 1 步：盘点组件

把设计稿里的元素归类，只保留**会重复出现**的：按钮、状态文字、数值行、面板、列表、输入框。一次性的装饰不要组件化。

产出：一张组件清单（名称 + 用途 + 状态）。

## 第 2 步：盘点状态

对每个组件列状态：默认、hover、focus、disabled、空、错误、长文案。设计稿没有画的，按现有实现补。

产出：组件 × 状态的矩阵。

## 第 3 步：抽取 token

从设计稿取颜色、字号、间距、圆角，写进 `src/tokens.ts`；能映射到 Tailwind 类的优先用类（如 `stone-900`）。

规则：一个 token 只出现一次；组件里不写魔法数字。

## 第 4 步：先写一个组件 + 三个 story

选最简单的按钮开始。组件只接受 props（纯展示），不加业务逻辑。

验收：Storybook 里能看到三种状态，Controls 能改参数。

## 第 5 步：按矩阵补故事

每个状态一个 story；用 `args` 表达差异，不复制组件。

## 第 6 步：设计评审

构建静态包 → 设计方打开 → 按「哪里、期望、为什么」提差异 → 改组件与 story。

## 第 7 步：固化

- 把 story 纳入版本库；
- 在 CI 里加一条 `storybook build`（本项目已加）；
- 每次 UI 改动都更新静态包。

## 不能直接迁移的部分

| Figma 内容 | 处理 |
|---|---|
| 战场画面（canvas 绘制） | 不迁；由渲染层负责，另做调试视图 |
| 复杂交互（拖拽、画布） | 写成交互测试或人工验收，不硬塞进 story |
| 像素级动效 | 以代码为准，Figma 仅参考 |
| 占位文案 | 换成真实结构的假数据，并补空状态 |

## 检查点

- [ ] 每个组件都有「默认 / 禁用 / 空或错误」至少三态
- [ ] token 只在 `tokens.ts` 与 Tailwind 类里出现
- [ ] 组件不 import 业务/引擎代码
- [ ] 静态包可离线打开
- [ ] 设计方确认过一次真实渲染
