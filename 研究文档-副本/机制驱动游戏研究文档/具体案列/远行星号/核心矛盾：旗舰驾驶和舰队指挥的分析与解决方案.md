# 《远行星号》战斗系统核心矛盾与“旗舰中心化”改造方案综述

## 一、问题提出与分析

### 1.1 核心元规则：攻防共享资源池

《远行星号》战斗系统的底层元规则只有一条：**攻击与防御争夺同一个资源池（辐能）**。

- **开火产生软辐能**：武器射击累积软辐能，可在护盾开启时被动消散。
- **护盾承伤产生硬辐能**：护盾吸收伤害累积硬辐能，**无法被动消散**，必须关闭护盾或手动排散才能清除。
- **过载惩罚**：辐能满时舰船完全瘫痪数秒，无法开火、开盾、排散。
- **辐能耗散是持续被动过程**：即使不操作，辐能也会缓慢下降。

这条元规则将“进攻”和“防守”从两个独立问题，强制转化为**同一个资源分配问题**。玩家每多开一枪，就少一分防御余裕；每多扛一秒，就少一分反击能力。这个耦合是整个战斗系统全部深度的唯一来源。

### 1.2 涌现出的核心体验

从这条元规则中，自下而上涌现出了完整的战术生态：

| 战术 | 机制原理 |
|:---|:---|
| **对射阵线** | 辐能是无限资源（可耗散），装甲结构是有限资源。一方不断后撤耗散软辐能，一方站桩输出，相当于无限资源交换有限资源 |
| **风筝拉扯** | 利用射程和机动性消耗对手辐能。对手辐能见底后撤排散时，是追击的最佳窗口 |
| **狼群集火** | 高机动部队集中火力，瞬间倾泻大量伤害，迫使目标累积大量硬辐能并最终过载，创造“斩杀窗口” |
| **留盾博弈** | 在护盾开启与关闭之间做出判断——开盾扛伤会产生硬辐能，关盾挨打会掉装甲 |

这套系统提供的核心体验是 **“高恐惧的实时资源博弈”**：过载=完全瘫痪数秒，一次失误可能直接输掉战斗；没有回合边界，玩家必须在压力下持续做决策；胜负手不是单纯的伤害比拼，而是对辐能状态的预判、诱骗和管理。

### 1.3 核心矛盾：旗舰操控与舰队指挥的认知冲突

《远行星号》战斗系统的精髓在于：玩家驾驶旗舰，同时组织一系列舰船组成不同战术编队发动攻击。但这存在一个根本问题：

**旗舰操控与舰队指挥是两套异质的认知模型，它们争夺同一份玩家认知资源。**

- **旗舰操控（具身化）**：要求玩家进入“驾驶舱”，关注连续的、局部的、高速的信息流——弹道、辐能、敌舰朝向。这是一种反应式、肌肉记忆驱动的模式。
- **舰队指挥（抽象化）**：要求玩家进入“指挥室”，关注离散的、全局的、延迟的信息流——各舰位置、任务状态、战场态势。这是一种策略式、全局判断驱动的模式。

战场太大，不可能一个界面把两个系统统合起来。玩家只能在不同界面折返，即使引入暂停，也只是部分缓解而非根治。因为战场的广度、战术的复杂度以及在此之上复杂的收益损失计算，哪怕暂停也很难弄清。反复折返暂停带来的体验崩坏，是结构性的。

**结果**：玩家经常顾此失彼，或干脆放弃一个转而拥抱另一个，让舰队玩法本身变得不伦不类。开发者Alex Sylvester也承认，游戏战斗“融合了俯视角射击和RTS元素，两者都对玩家的注意力提出了很高的要求”。

## 二、原理解释：为什么之前的改造方案不够格

针对上述矛盾，此前讨论过多个改造方案，它们可以归为三类：

### 2.1 信息层改造
- **方案A**：辐能条离散化、过载预警、战斗复盘。
- **方案D**：AI行为透明化、降低AI计算精度。

**评价**：这些方案**不改变底层规则**，只是让信息更可见。它们能降低新手挫败感，但**无法解决认知模型冲突**。玩家依然需要在两套认知模式间切换，只是切换时看得更清楚。

### 2.2 惩罚曲线改造
- **方案B**：将过载从“完全瘫痪”改为“红线区性能衰减”。

**评价**：这保留了攻防共享资源池的核心张力，但**只解决了旗舰操控内部的容错问题**，完全没有触及舰队指挥与旗舰操控的矛盾。它让旗舰驾驶更友好，但舰队指挥的认知负担依然存在。

### 2.3 平行系统与指挥优化
- **方案C**：派系声望、舰船改装、电子战等非战斗优势。
- **第二指挥官**：AI副官全权指挥除旗舰外的舰队。
- **群体指令/编队系统**：用群体指令替代微观管理。
- **预设行为模式**：战前设定“狼群”“铁壁”等模式，战中切换。

**评价**：这些方案试图在**不改变“双认知模型”的前提下**，降低切换频率和成本。但问题在于：
- 预设模式无法覆盖动态战场，遭遇意外仍需主动切换，本质仍是认知切换。
- AI副官无法替代玩家决策，玩家依然会担心AI决策，产生“检查”冲动。
- 群体指令降低了操作频率，但没降低认知负荷——判断“现在该用哪种指令”本身就需要从驾驶舱模式中抽离出来，进行全局态势评估。

**根本问题**：这些方案解决的是“操作繁琐”，而不是“认知冲突”。只要玩家既需要“驾驶”，又需要“指挥”，这个矛盾就永远存在。任何方案都只能缓解症状，而无法消除病因。

## 三、最终论述方案：旗舰中心化的舰队资产重构

### 3.1 核心设计哲学

**将舰队从“战中需要指挥的资产”重新定义为“战前需要配置、战中自主行动、战后需要重建的资产”。玩家在战中只做一件事——驾驶旗舰。**

这一方案彻底取消了战中的舰队指挥行为，从而**根治了认知模型冲突**。它不是在旧身份上打补丁，而是**重新定义了游戏的身份**：玩家不再是“舰队司令+旗舰驾驶员”，而是纯粹的“旗舰驾驶员”，舰队则是围绕旗舰配置的辅助资产。

### 3.2 具体机制描述

#### 3.2.1 战前配置：舰队玩法的全部深度所在

战中完全没有舰队指挥，因此**战前配置成为舰队玩法的唯一载体**。玩家需要在战斗前完成以下决策：

- **舰船选择**：选择舰船种类和数量。不同舰船有不同定位（突击、支援、防御、电子战等）。
- **武器与装备配置**：为每艘舰船配置武器、护盾、引擎、辅助系统。这决定了舰船在战斗中的行为倾向。
- **行为准则设定**：为每艘舰船或每个编队设定自主行为准则，例如：
  - “跟随旗舰，保持中距离”
  - “优先攻击敌方导弹舰”
  - “当护盾低于30%时后撤排散”
  - “当旗舰被集火时，主动吸引火力”
- **编队阵型**：设定舰队在战斗中的初始阵型和相对位置关系。

这些决策必须**足够有深度**，才能让“舰队”不沦为纯粹的数字堆砌。战前配置的深度，直接决定了舰队存在的意义。

#### 3.2.2 战中行为：完全自主，无需指挥

战斗开始后，所有非旗舰舰船**完全自主运行**，按照战前配置的行为准则行动。玩家**没有任何指挥操作**——没有指挥点，没有任务系统，没有战场地图，没有编队指令。

- **舰队AI的职责**：根据自身状态、敌方状态和预设行为准则，自主决定移动、开火、排散、后撤等行为。
- **AI行为必须可读且可靠**：玩家不指挥舰队，但必须能理解舰队在做什么。需要清晰的视觉反馈（舰船在做什么？为什么？），行为准则需要可预测（设定“优先攻击导弹舰”后，AI应该真的优先攻击导弹舰），异常情况需要可感知（某艘舰船被集火、脱离阵型，玩家应能通过UI感知到）。
- **旗舰与舰队的互动**：舰队必须以某种方式影响旗舰的体验。舰队可以吸引火力，为旗舰创造输出窗口；可以提供支援（维修、护盾、电子战）；舰队的损失会影响战后资源状态，形成战后压力。某些战术（如“狼群集火”）可以由舰队自主执行，玩家只需要**利用**这些行为，而不是**指挥**它们。

#### 3.2.3 战后重建：可再生机制

- **战斗中**：舰船被击毁后不会再生。旗舰被击毁=战斗失败（或至少是重大挫折）。旗舰是**唯一不可替代的节点**。
- **战斗结束后**：舰队自动重建。但重建需要消耗**战后资源**（如金钱、材料、时间）。战中不需要玩家操心，战后需要玩家做资源分配决策。
- **损失的意义**：舰船损失不再是战中的认知负担，而是**战后的资源压力**。玩家需要在“快速重建以应对下一场战斗”和“节省资源用于其他发展”之间做出权衡。

#### 3.2.4 旗舰的不可替代性

- 旗舰被击毁 = 战斗失败（或至少是重大挫折）。
- 旗舰的生存是玩家的**首要且唯一**的战斗目标。
- 舰队的存在意义是**保护旗舰、辅助旗舰、为旗舰创造机会**。

这实际上和《星际火狐》或《皇牌空战》的僚机系统非常相似——僚机存在，但玩家只关心自己的飞机。区别在于，这里的“僚机”拥有**战前配置的深度**和**战后重建的资源压力**，从而保留了《远行星号》舰队玩法的策略维度。

### 3.3 与不够格方案的对比

| 方案 | 核心思路 | 为何不够格 |
|:---|:---|:---|
| **信息层改造** | 辐能可视化、过载预警、AI透明化 | 不改变底层规则，无法解决认知模型冲突。玩家仍需在两种模式间切换 |
| **惩罚曲线改造（红线区）** | 过载从瘫痪改为性能衰减 | 只解决旗舰操控内部的容错问题，完全未触及舰队指挥与旗舰操控的矛盾 |
| **平行系统** | 声望、改装、电子战等非战斗优势 | 为战斗受挫提供替代路径，但舰队指挥的认知负担依然存在 |
| **第二指挥官** | AI副官全权指挥舰队 | AI无法替代玩家决策，玩家依然会担心AI决策，产生“检查”冲动，认知切换依旧 |
| **群体指令/编队系统** | 用群体指令替代微观管理 | 降低操作频率，但没降低认知负荷——判断“现在该用哪种指令”本身就需要从驾驶舱模式抽离 |
| **预设行为模式** | 战前设定模式，战中切换 | 遭遇意外仍需主动切换，本质仍是认知切换 |
| **最终方案：旗舰中心化** | **战中完全取消舰队指挥，舰队自主行动，战后可再生** | **彻底消除两套认知模型的冲突，将舰队玩法完全转移到战前配置与战后资源管理** |

### 3.4 方案在游戏设计谱系中的位置

| 游戏 | 舰队/僚机定位 | 战中指挥 | 损失代价 |
|:---|:---|:---|:---|
| 《远行星号》 | 需要指挥的资产 | 低频但存在 | 永久 |
| **最终方案** | **需要配置的资产** | **完全不存在** | **战后可再生** |
| 《星际火狐》 | 自动僚机 | 无 | 无 |
| 《皇牌空战》 | 自动僚机 | 无 | 无 |
| 《家园》 | 需要指挥的舰队 | 高频 | 永久 |

最终方案位于《远行星号》和《星际火狐》之间：它保留了《远行星号》的**舰队配置深度**和**旗舰操控核心**，但采用了《星际火狐》的**战中零指挥**和**僚机可再生**逻辑。

## 四、结论

《远行星号》战斗系统的核心矛盾，源于旗舰操控与舰队指挥两套异质认知模型在同一个实时环境中的根本性冲突。这一冲突无法通过界面优化、惩罚调整或指挥辅助来“解决”，只能通过设计取舍来“管理”。

**最终方案：旗舰中心化的舰队资产重构**，将舰队从“战中需要指挥的资产”重新定义为“战前需要配置、战中自主行动、战后需要重建的资产”。玩家在战中只做一件事——驾驶旗舰。这一方案彻底消除了认知模型冲突，同时保留了舰队玩法的策略深度（通过战前配置）和资源压力（通过战后重建）。

对个人开发者而言，这一方案**理论自洽、开发友好、成本可控**。它不需要复杂的指挥AI、战场地图UI或指挥点系统，将开发精力集中在**旗舰操控 + 辐能管理 + 战前配置**三个核心系统上。它是对《远行星号》核心矛盾最彻底的解决方案，也是新项目最可行的设计起点。
