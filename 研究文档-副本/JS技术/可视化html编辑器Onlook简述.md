Onlook 是一个定位独特的开源可视化编辑器，它**专为 React 代码库设计**，核心理念是让设计师直接在**真实的、正在运行的代码**上进行可视化编辑，并将改动实时写回源代码，而非生成独立的原型文件。

### 📜 许可模式：Apache 2.0 开源，自托管免费

Onlook 的许可策略清晰且宽松：**核心代码库采用 Apache-2.0 许可证开源**。

这意味着你可以**免费、自由地用于商业用途**，包括修改、分发，甚至将其集成到闭源项目中，无需支付版税或公开你的源代码。官方提供的**自托管版本完全免费**，你可以在自己的服务器上运行它。

需要留意的是，Onlook 同时提供一个**托管的云版本**，该版本目前处于**封闭测试**阶段，主要面向企业团队，采用定制报价。对于追求完全掌控和零成本的团队，自托管是首选路径。

### 🏗️ 架构：DOM 映射与代码回写

Onlook 的核心架构可以概括为 **“浏览器中的设计工具 + 代码回写引擎”**。

**视觉编辑层**
Onlook 本质上是一个指向你本地开发服务器的浏览器。它通过 **iframe** 加载你运行中的 React 应用，并像 Chrome DevTools 一样操作 DOM。所有视觉改动（拖拽、调整大小、修改样式）会先通过注入的 CSS 样式表或 DOM 操作**实时反映在 iframe 中**，但这些改动在写回代码前是**非持久化的**。

**代码回写引擎**
这是 Onlook 实现“设计即代码”的关键。在构建时，Onlook 会向 DOM 元素注入一个类似 **sourcemap 的属性**，该属性指向源代码中的具体位置和组件作用域。当你在视觉界面完成编辑后，引擎会**解析源代码为 AST**，将样式或结构改动注入，然后**写回你的本地代码库**。这个过程是**框架无关的**，理论上可以支持任何声明式渲染 DOM 的框架。

**Action 系统与协作基础**
所有编辑操作都被存储为 **Action**。这种设计使改动可序列化、可存储、可复现，为未来的**在线协作**或 **AI Agent 生成 Action** 奠定了基础。

**Monorepo 技术栈**
项目采用 **Bun** 管理的 Monorepo 结构。前端基于 **Next.js + React + TypeScript**，样式使用 **TailwindCSS**；后端依赖 **Supabase** 处理数据库、认证和存储，并通过 **Drizzle ORM** 进行数据层管理；AI 模块集成了 AI SDK 和 Anthropic 作为 LLM 提供商。

### 🎨 可视化能力：Figma 式交互，代码为源

Onlook 的可视化编辑体验接近 **Figma**，但所有操作都直接关联真实代码。

**核心编辑操作**
- **拖拽与布局**：像在 Figma 中一样拖拽组件、调整元素大小和位置。
- **样式编辑**：通过可视化界面修改 **Tailwind CSS** 样式，无需手写类名。
- **文本与图片**：直接编辑文本内容，管理项目中的图片资源。

**代码与设计的双向同步**
- **实时代码预览**：编辑的同时，**Code Panel** 会显示生成的代码改动。
- **设计稿导入**：支持从 **Figma** 导入设计稿，并将其转换为可交互的 React 组件。
- **AI 辅助**：集成 AI 聊天功能，可根据描述生成组件、提供改进建议，或帮助调试问题。

**画布与交互模式**
编辑器画布由 **Frames（可编辑画板）** 和 **Gesture Screen（手势层）** 构成。手势层提供两种模式：**Action 模式**下所有事件穿透到网页，保持正常浏览；**Design 模式**下捕获所有事件（点击、悬停、滚动）用于编辑交互。

### 🔗 与其他 JS 代码库的适应性

Onlook 的适配策略是 **“框架无关的架构，React 优先的实现”**。

**官方明确支持**
- **React 生态全覆盖**：Onlook 可在 **任何 React 代码库**上运行，包括 **Next.js（App Router 和 Pages Router）、Vite、Remix、Astro（React 模式）以及标准的 Create React App** 项目。
- **TailwindCSS 深度集成**：目前对 **TailwindCSS** 的支持最为成熟，能够读取项目的 Tailwind 配置、主题令牌和设计系统。
- **Storybook 支持**：提供 `@onlook/storybook-plugin`，可集成到 Storybook 工作流中。

**当前边界**
- **React-only**：尽管架构理论上框架无关，但**目前官方实现仅支持 React**，**不支持 Vue、Svelte 或纯 HTML** 项目。
- **需要构建时注入**：使用 Onlook 需要为你的编译步骤添加一个插件（通常只需 **2 行配置改动**），以支持代码位置映射。

### 💎 总结

Onlook 的定位可以概括为：**面向 React 团队的 Apache-2.0 开源可视化编辑器，以真实代码为唯一数据源，自托管免费可商用**。它通过 DOM 映射与 AST 回写技术，在“可视化设计”与“真实代码”之间建立了直接的桥梁，消除了传统 Figma-to-Code 工作流中的交接损耗。对于已经在使用 React + TailwindCSS 技术栈、希望引入可视化编辑能力且对开源许可有严格要求的团队，Onlook 是一个值得深入评估的选择。
