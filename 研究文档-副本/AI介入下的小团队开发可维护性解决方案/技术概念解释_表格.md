# 先回答：CI 是什么

**CI（Continuous Integration，持续集成）** 是一种开发实践和配套的自动化系统。核心规则是：**开发者频繁地把代码合并到主干，每次合并都自动触发构建、测试和检查**。

### 为什么需要 CI
没有 CI 时，多人各写各的，几周甚至几个月才合并一次，合并时大量冲突、隐藏 bug 集中爆发，叫“集成地狱”。CI 让问题在产生的当天就被发现。

### CI 的典型流程
1. 开发者从版本控制拉取代码，写完提交到分支。
2. 发起 **PR（Pull Request，合并请求）**。
3. CI 系统自动触发：
   - **构建**：把源码编译成可执行文件或库。
   - **单元测试**：测单个函数/类。
   - **集成测试**：测多个模块协作。
   - **契约测试**：测接口语义是否符合约定。
   - **架构约束测试**：测代码是否违反架构规则。
   - **静态检查**：代码风格、潜在 bug、依赖漏洞。
4. 全部通过 → 允许合并到主干；任一失败 → 阻止合并，通知开发者修复。
5. 合并后可能继续触发 **CD（Continuous Delivery/Deployment，持续交付/部署）**，自动发布到测试或生产环境。

### 人如何接触 CI
- 提交代码后，在 PR 页面看到 CI 报告。
- 失败时根据日志修复，重新提交。
- 维护 CI 配置（如 `.github/workflows/ci.yml`、`Jenkinsfile`）。
- 设置 **CI Gate**：CI 中的检查点，失败则阻止合并。

### CI Gate 与权限分层
在之前架构中，CI 不只是跑测试，还承担 **权限分层**：
- **AUTO Gate**：AI 改模块内部实现，CI 通过即自动合并。
- **SOFT Gate**：AI 新增模块边界，CI 通过后人类异步审查。
- **HARD Gate**：AI 改根契约或热路径核心，CI 通过后仍需人类审批。

**因果链到此为止**：版本控制、构建、测试是 CI 的基础，不再往下溯源。

# 上文中提到的概念详解

按“人需要直接或间接接触”分类。每个概念给：是什么、为什么、人怎么接触。因果链超过三层就停。

---

## 一、开发流程与协作

### 1. 版本控制（Version Control）
- **是什么**：记录代码每次修改的历史，支持分支、合并、回滚。Git 是最常用的。
- **为什么**：多人协作不互相覆盖，出问题可回到旧版本。
- **人怎么接触**：`git commit`、`git push`、`git pull`、创建分支、解决冲突。

### 2. PR / MR（Pull Request / Merge Request）
- **是什么**：请求把某个分支的代码合并到主干。
- **为什么**：合并前让 CI 跑检查、让人类审查。
- **人怎么接触**：在 GitHub/GitLab 上发起 PR，看评论，修改后重新推送。

### 3. 代码审查（Code Review）
- **是什么**：人类看别人的代码，检查逻辑、风格、安全、架构合规。
- **为什么**：AI 生成代码快，但可能语义错误或违反约束，人类审查是最后防线。
- **人怎么接触**：在 PR 中留言、批准或要求修改。

### 4. 构建系统（Build System）
- **是什么**：把源码、资源、依赖打包成可运行程序的工具链。如 CMake、Bazel、MSBuild。
- **为什么**：手动编译几百个文件不现实。
- **人怎么接触**：写构建脚本，运行 `build` 命令。

### 5. 编译器（Compiler）
- **是什么**：把源代码翻译成机器码或字节码。如 GCC、Clang、C# 编译器。
- **为什么**：计算机只懂机器码。
- **人怎么接触**：构建时自动调用，出错看编译错误。

### 6. 动态库（Dynamic Library）
- **是什么**：运行时才加载的库，Windows 是 `.dll`，Linux 是 `.so`，macOS 是 `.dylib`。
- **为什么**：支持模块独立编译、热重载、减小主程序体积。
- **人怎么接触**：把模块编译成动态库，运行时加载。

### 7. 增量编译（Incremental Build）
- **是什么**：只重新编译改动的文件，不重编整个项目。
- **为什么**：大型项目全量编译几十分钟，增量编译几秒。
- **人怎么接触**：构建系统自动判断，开发者无感。

### 8. 回滚（Rollback）
- **是什么**：把代码或运行时状态恢复到之前版本。
- **为什么**：新版本出问题，快速恢复。
- **人怎么接触**：Git 回退、CI 一键回滚、热重载失败自动回滚。

### 9. 熔断（Circuit Breaker）
- **是什么**：某模块连续失败 N 次后，自动停止调用它，降级到安全模式。
- **为什么**：防止一个坏模块拖垮整个系统。
- **人怎么接触**：配置熔断阈值，看监控告警。

### 10. 可观测性（Observability）
- **是什么**：通过日志、指标、追踪，了解系统内部运行状态。
- **为什么**：出问题能快速定位。
- **人怎么接触**：看仪表盘、查日志、分析调用链。

### 11. SRE（Site Reliability Engineering）
- **是什么**：用软件工程方法做运维，保证系统可靠性。
- **为什么**：超大型系统需要专职可靠性保障。
- **人怎么接触**：小团队通常兼任，大公司有 SRE 团队。

## 二、接口与通信

### 12. IDL（Interface Definition Language）
- **是什么**：与编程语言无关的接口定义格式。
- **为什么**：不同语言模块之间需要共同语言。
- **人怎么接触**：写 `.proto`、`.thrift` 等文件，构建系统生成代码。

### 13. 桩代码（Stub Code）
- **是什么**：IDL 编译器自动生成的代理代码，负责序列化、通信、调用真实实现。
- **为什么**：让跨模块/跨语言调用像本地函数一样简单。
- **人怎么接触**：不手写，只调用生成的接口。

### 14. Protobuf（Protocol Buffers）
- **是什么**：Google 的 IDL 和序列化格式，二进制高效。
- **为什么**：网络通信、存档常用。
- **人怎么接触**：写 `.proto`，生成各语言类。

### 15. FlatBuffers
- **是什么**：Google 的零拷贝序列化格式。
- **为什么**：游戏热路径每帧读数据，不需要反序列化。
- **人怎么接触**：定义 schema，生成访问代码。

### 16. Thrift
- **是什么**：Apache 的跨语言 RPC 框架和 IDL。
- **为什么**：企业级服务通信。
- **人怎么接触**：写 `.thrift`，生成客户端/服务端桩。

### 17. TypeScript interface
- **是什么**：TypeScript 的接口类型，编译期检查。
- **为什么**：前端/工具链轻量契约。
- **人怎么接触**：写 `interface`，编译器检查。

### 18. Rust trait
- **是什么**：Rust 的接口抽象，类似接口但更强大。
- **为什么**：Rust 模块间编译期解耦。
- **人怎么接触**：定义 `trait`，实现 `impl`。

### 19. 序列化 / 反序列化
- **是什么**：把对象转成字节流 / 把字节流转回对象。
- **为什么**：跨进程、跨网络、存档需要。
- **人怎么接触**：IDL 自动生成，一般不手写。

### 20. IPC（Inter-Process Communication）
- **是什么**：进程间通信，如管道、共享内存、消息队列。
- **为什么**：多进程架构中进程需要交换数据。
- **人怎么接触**：通过 Mojo、gRPC 等框架，不直接写系统调用。

### 21. RPC（Remote Procedure Call）
- **是什么**：像调用本地函数一样调用远程服务。
- **为什么**：微服务、分布式系统常用。
- **人怎么接触**：通过 gRPC、Thrift 等框架。

### 22. 事件总线（Event Bus）
- **是什么**：发布/订阅中枢，发布者发事件，订阅者收事件，互不知道对方。
- **为什么**：跨模块解耦。
- **人怎么接触**：定义事件、发布、订阅。

### 23. 同步事件 / 异步队列事件
- **同步事件**：发布后立即调用订阅者，帧内响应，阻塞发布者。
- **异步队列事件**：事件入队，帧末统一处理，不阻塞，延迟一帧。
- **人怎么接触**：根据场景选择发布方式。

### 24. 命令缓冲（Command Buffer）
- **是什么**：不直接改状态，把修改意图入队，帧末统一执行。
- **为什么**：避免迭代器失效、顺序依赖。
- **人怎么接触**：发 `Spawn`、`Destroy` 等命令，帧末 `flush`。

### 25. 门面接口（Facade）
- **是什么**：模块对外唯一入口，隐藏内部实现。
- **为什么**：减少耦合，AI 只读门面。
- **人怎么接触**：每个模块暴露一个 Facade 类/接口。

### 26. DI（Dependency Injection，依赖注入）
- **是什么**：依赖从外部注入，不在内部创建。
- **为什么**：编译期解耦，方便替换和测试。
- **人怎么接触**：构造函数传接口，或使用 DI 容器。

### 27. 服务定位器（Service Locator）
- **是什么**：全局容器，模块主动从中拉取服务。
- **为什么**：灵活，但隐藏依赖。
- **人怎么接触**：`locator.get<IAudio>()`。

### 28. DI 容器
- **是什么**：自动解析依赖图并注入的框架。
- **为什么**：复杂项目减少手动组装。
- **人怎么接触**：注册接口和实现，容器自动创建。

### 29. Mock
- **是什么**：测试用的假实现，模拟真实对象行为。
- **为什么**：单元测试不依赖真实数据库/网络。
- **人怎么接触**：测试时注入 Mock。

## 三、数据与性能

### 30. ECS（Entity-Component-System）
- **是什么**：实体是 ID，组件是数据，系统是逻辑。
- **为什么**：数据导向，缓存友好，易并行。
- **人怎么接触**：定义组件、写系统、查询。

### 31. SoA（Structure of Arrays）
- **是什么**：按属性拆数组，如 `pos[10000]`、`vel[10000]`。
- **为什么**：缓存命中率高，遍历快。
- **人怎么接触**：ECS 内部自动用，开发者写 Query。

### 32. AoS（Array of Structures）
- **是什么**：每个对象存所有属性，如 `Particle[10000]`。
- **为什么**：直观，但遍历时缓存差。
- **人怎么接触**：传统 OOP 常用。

### 33. 数据导向（Data-Oriented Design）
- **是什么**：按数据访问模式组织内存，而不是按对象。
- **为什么**：CPU 缓存决定性能。
- **人怎么接触**：热路径用 SoA，冷路径随意。

### 34. 零拷贝（Zero-Copy）
- **是什么**：数据不复制，直接访问原内存。
- **为什么**：减少内存带宽和延迟。
- **人怎么接触**：FlatBuffers、共享内存。

### 35. 缓存命中（Cache Hit）
- **是什么**：CPU 要的数据在缓存中，直接读。
- **为什么**：命中快，未命中慢几十倍。
- **人怎么接触**：SoA、数据局部性提高命中率。

### 36. 热路径 / 冷路径
- **热路径**：每帧执行、性能敏感，如渲染、物理。
- **冷路径**：事件驱动、可延迟，如任务、UI。
- **人怎么接触**：热路径直连，冷路径事件。

## 四、运行时与隔离

### 37. 模块化单体（Modular Monolith）
- **是什么**：一个部署单元，但内部模块严格隔离。
- **为什么**：小团队避免微服务运维成本，又享受解耦。
- **人怎么接触**：按模块划分代码，走接口通信。

### 38. 微服务（Microservices）
- **是什么**：独立部署的服务，通过网络通信。
- **为什么**：独立扩展、独立发布。
- **人怎么接触**：服务发现、API 网关、容器编排。

### 39. 垂直切片（Vertical Slice）
- **是什么**：按玩家可见功能端到端开发，而不是按技术层。
- **为什么**：AI 可独立完成一个切片，快速验证。
- **人怎么接触**：一个切片包含 UI、逻辑、数据。

### 40. 热重载（Hot Reload）
- **是什么**：不重启程序，替换动态库，保留状态。
- **为什么**：迭代从分钟级降到秒级。
- **人怎么接触**：改代码，自动重载。

### 41. 沙箱 VM（Sandbox VM）
- **是什么**：第三方代码在受限环境运行，只能调暴露 API。
- **为什么**：Mod/脚本崩溃不影响引擎。
- **人怎么接触**：写 Mod 用沙箱 API。

### 42. Lua
- **是什么**：轻量脚本语言，游戏 Mod 常用。
- **为什么**：易嵌入，性能可接受。
- **人怎么接触**：写 `.lua` 脚本。

### 43. WASM（WebAssembly）
- **是什么**：可移植的二进制指令格式，浏览器/引擎通用。
- **为什么**：性能好，语言无关。
- **人怎么接触**：把 C++/Rust 编译成 `.wasm`。

### 44. C# AppDomain
- **是什么**：.NET 的隔离容器。
- **为什么**：Unity 常用，隔离插件。
- **人怎么接触**：加载程序集到 AppDomain。

### 45. V8
- **是什么**：Google 的 JavaScript 引擎。
- **为什么**：Node.js、Chrome 用，工具链可嵌。
- **人怎么接触**：写 JS，V8 执行。

### 46. 崩溃隔离
- **是什么**：一个模块崩溃不影响其他模块。
- **为什么**：多进程/沙箱实现。
- **人怎么接触**：模块独立进程/动态库。

## 五、测试与治理

### 47. 单元测试（Unit Test）
- **是什么**：测单个函数/类，不依赖外部。
- **为什么**：快速定位错误。
- **人怎么接触**：写 `TEST` 用例。

### 48. 集成测试（Integration Test）
- **是什么**：测多个模块协作。
- **为什么**：单元测试都过，集成可能失败。
- **人怎么接触**：启动部分系统，发事件验证。

### 49. 契约测试（Contract Test）
- **是什么**：验证实现是否符合接口语义。
- **为什么**：AI 生成代码可能语义错误。
- **人怎么接触**：人类写测试，AI 不能改。

### 50. 架构约束测试（Architecture Fitness Test）
- **是什么**：自动检查代码是否符合架构规则。
- **为什么**：人工审查不可靠。
- **人怎么接触**：CI 中运行，失败阻止合并。

### 51. 能力注册表（Capability Registry）
- **是什么**：系统能力的权威清单。
- **为什么**：AI 查表复用，避免重复实现。
- **人怎么接触**：YAML 文件，CI 维护。

### 52. Spec（Specification）
- **是什么**：功能的权威描述，含类型、语义、测试。
- **为什么**：人类和 AI 的共同语言。
- **人怎么接触**：写 Spec，审批后 AI 实现。

### 53. 影响分析（Impact Analysis）
- **是什么**：自动计算变更影响哪些模块。
- **为什么**：评估风险，决定审批级别。
- **人怎么接触**：CI 报告附影响范围。

### 54. 依赖图（Dependency Graph）
- **是什么**：模块间依赖关系图。
- **为什么**：影响分析、并行调度。
- **人怎么接触**：构建系统自动生成。

### 55. HARD / SOFT / AUTO Gate
- **HARD**：破坏性变更，必须人类审批。
- **SOFT**：增量变更，异步审查。
- **AUTO**：内部实现，CI 通过即合并。
- **人怎么接触**：CI 自动分类，人类处理 HARD。

## 六、其他架构思想

### 56. Actor 模型
- **是什么**：每个 Actor 是独立单元，只通过消息通信。
- **为什么**：天然分布式、容错。
- **人怎么接触**：Erlang/OTP、Akka。

### 57. 端到端原则（End-to-End Principle）
- **是什么**：网络核心保持简单，智能放端系统。
- **为什么**：微内核、Unix 哲学。
- **人怎么接触**：核心只提供 IPC，功能外挂。

### 58. 逻辑网络 / 物理网络
- **逻辑网络**：系统内部模拟网络，节点是进程/模块，协议是 IPC/事件。
- **物理网络**：真实服务器组成的网络，协议是 TCP/IP。
- **人怎么接触**：逻辑网络用 Mojo、gRPC；物理网络用 HTTP。

### 59. 服务网格（Service Mesh）
- **是什么**：微服务间的通信基础设施，负责负载均衡、熔断、追踪。
- **为什么**：服务间通信复杂，抽离到基础设施。
- **人怎么接触**：Istio、Linkerd。
