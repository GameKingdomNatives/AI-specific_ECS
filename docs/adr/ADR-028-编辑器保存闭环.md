# ADR-028 编辑器保存闭环（S5a：Vite 插件写盘）

- 状态：已接受（S5a）
- 日期：2026-10-22
- 相关：`docs/audits/场景编辑器计划.md` S5、ADR-024

## 背景

S3/S4 的编辑器只改内存；要让 scene JSON 真正成为工作流的一部分，需要「保存到项目文件」的闭环。浏览器不能直接写盘，因此由 Vite dev server 提供受控保存端点。

## 决策

1. **插件形态**：`apps/game/scene-save-plugin.mjs`，`apply: 'serve'`，只在 dev server 注册 `POST /__scene/save`；生产构建无此端点。
2. **请求**：`{ file: "<name>.scene.json", scene: <scene 文档> }`，body 上限 1MB。
3. **校验顺序**：JSON 解析 → 文件名 / 路径守卫（只允许字母/数字/._-，必须 `.scene.json`，resolve 后必须仍在 `apps/game/scenes/`）→ `parseScene` 全量校验；任一失败返回 400 + 可读错误/issue 清单，不落盘。
4. **原子写**：写 `<target>.tmp-<pid>` 后 `rename` 覆盖；避免半截文件。目录固定为 `server.config.root/scenes`。
5. **客户端**：`SaveButton` POST 保存，成功后回调 `reload` 重新读 `/scenes/demo.scene.json` 并用 `parseScene` 复验——形成「改→保存→从磁盘重载」闭环。
6. **错误呈现**：按钮显示「保存中/已保存（字节数）/保存失败 + 原因」，不写 console 静默。

## 验收

- API：合法保存返回 `{ok:true, bytes:649}`；`file='../evil.scene.json'` 返回 400；`schemaVersion=2` 返回 400。
- 浏览器：编辑器加子节点 → 保存 → 文件节点 3→4、面板显示「已保存」且自动重载后仍是 4 节点。
- 单测：无（插件是 dev 工具，走 API + 浏览器证据）；全量门禁 PASS。

## 已知限制

- 仅 dev server；生产无权写盘（符合「本地 + 免费」工作流）。
- 固定文件名 `demo.scene.json`（S6/后续可编辑器选择文件）。
- 无写锁/版本比较：多个编辑器同时保存以最后一次为准（本地单人工作流可接受）。
- 运行时主循环仍走代码路径；scene 已能保存与重载，但「保存后游戏世界重建」属于 S5b。
