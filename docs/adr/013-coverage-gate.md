# ADR-013 覆盖率门禁（下限保护）

- 状态：已接受
- 日期：2026-10-21
- 相关：R4 质量补强、`tools/gate.mjs`、`tools/coverage.mjs`

## 背景

门禁此前只跑测试，不检查「测试覆盖到多少」；新增代码可以把大量分支留空仍然全绿。需要一条低成本、无新依赖的下限保护。

## 决策

1. **采集**：门禁里已有的「逐文件直跑测试」步骤统一注入 `NODE_V8_COVERAGE=<run>/coverage`，由 Node 自己写 JSON；不额外跑第二遍测试、不 spawn 管道子进程（沙箱限制）。
2. **统计**：`tools/coverage.mjs` 读取 JSON，按 V8 block coverage 的**最内层区间**判定每一行是否命中（外层函数区间会虚高，故不采用）；范围限定 `packages/engine/src`。
3. **阈值**：整体行覆盖率 ≥ **70%**，作为 `coverage` 步骤进门禁；当前实测 **81.7%**（1957/2396）。阈值只作下限，不追求语句级精确。
4. **实现取舍**：V8 报告的是编译后的 `dist/src/**/*.js`，脚本按路径映射回 `src/**/*.ts` 展示文件名；行号沿用编译产物（tsc 未压缩，结构接近），因此这是**近似读数**，不是行级精确覆盖。
5. **保护路径**：`tools/gate.mjs` 与新增 `tools/coverage.mjs` 属保护路径，本次按 `ALLOW_PROTECTED=1` 修改并记录于本 ADR。

## 后果

- 正面：覆盖率成为门禁事实；无需 c8/nyc 等会 spawn 的工具；测试只跑一遍。
- 代价：读数是近似值；`dist` 与 `src` 行号可能轻微漂移；阈值要随代码增长维护。
- 回退：删除 `coverage` 步骤即可，不影响测试本身。

## 验收

- `node tools/gate.mjs` 输出 `coverage PASS` 且打印引擎源码覆盖率；
- 人为删掉一批测试后覆盖率跌破 70% 时步骤应为 FAIL；
- 全量门禁 38 步 PASS（2026-10-21 实测）。
