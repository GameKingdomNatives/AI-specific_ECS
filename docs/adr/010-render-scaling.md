# ADR-010 渲染规模化：剔除、池化与基准

- 状态：已接受
- 日期：2026-10-21
- 相关：ADR-002（UI 与战场分层）、`docs/audits/next-direction.md`

## 背景

逻辑帧 3000 实体 0.788ms（预算 4ms）已达标，但渲染表每帧全量提交、每实体一个 Container、纹理变化即销毁重建、失败回退几何；没有任何剔除或统计。目标类型是俯视弹幕/STG，实体量级会从几十涨到数千，渲染是下一堵墙。

## 决策

1. **相机 AABB 剔除**：由渲染后端内部根据 camera 与窗口尺寸计算可见区域（与相机变换同口径），`RenderItem` 只按「中心 + 尺寸 + 余量」判定；不改 `IRenderer` 端口。
2. **视图池化**：按形状（`shape:*`）与贴图（`tex:*`）分池复用 `Graphics`/`Sprite`；实体消失或纹理切换时释放回池，不 `destroy()`；渲染器销毁时清池。
3. **代际清理**：`View.lastSeen` 记录帧号，替代每帧新建 `Set`，避免热路径分配。
4. **统计**：`PixiRenderer` 返回 `stats()`（total/submitted/culled/views/pooled）与 `setCulling()`；这是实现的附加能力，不是端口变更。
5. **图集暂缓**：当前只有 player/box/bullet 三张贴图，合图收益无法测量；等单场景贴图种类或 Sprite 数量跨过阈值（建议 >32 张或 >2000 Sprite）再引入，引入时仍不改端口（可把帧包进合成 URL 或在实现层解析清单）。
6. **基准**：新增 `tools/render-bench.mjs`，固定种子 10000 项、8000×6000 世界、1920×1080 视口，预算 4ms/趟；作为门禁 `render-bench` 步骤。

## 修订（2026-10-21，基准方法）

首次接入后用 5 轮无预热 + 容差 1.5，出现 0.507 vs 0.9 的噪声性失败。改为：**9 轮、前 2 轮预热、取剩余中位；容差 2.0；预算 4ms 不变**。理由：微基准受 JIT/系统负载影响，预热后中位更稳定；硬预算仍卡 4ms，容差只防基线漂移。以此重新生成 `tools/render-bench-baseline.json`（0.453ms）。

## 后果

- 正面：视野外实体不再提交；实体增删不再反复创建/销毁节点；渲染侧第一次有可读读数，可进回归。
- 代价：视图池会常驻一批节点（内存换分配）；剔除在超高缩放/极小视口下比例更极端，需基准兜底。
- 端口：无变化（HARD 未触发）；`tools/gate.mjs` 为保护路径，本次按 `ALLOW_PROTECTED=1` 修改并记录于本 ADR。

## 验收

- `node tools/gate.mjs` 通过（含 `render-bench`）；
- 浏览器实测：`__itb.render()` 可读，zoom 2.5 时剔除生效，开火/停火时 `views` 与 `pooled` 互补（复用而非累积）；
- 5000–10000 项基准耗时 ≤ 4ms，且不超过基线 2.0 倍（见修订段）。
