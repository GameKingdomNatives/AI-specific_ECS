# ADR-032 原地重建：编辑器保存后不刷新页面（D3）

- 状态：已接受（D3）
- 日期：2026-10-22
- 相关：ADR-029/030/031、`docs/audits/数据驱动运行时计划.md`

## 背景

S5b/D2 保存后依赖 Vite watcher 触发整页 reload：世界能重建，但编辑器关闭、选中/滚动丢失，用户看到的「实时修改」被刷新打断。目标是把「保存 → 世界重建」变成当前页面内的一次事务。

## 决策

1. **运行时字段可变**：`main.ts` 的 `world / sceneResult / player / deps / scheduler / runState / recorder` 改为模块级 `let`；渲染循环与调试 API 闭包引用这些变量，重建后自然指向新世界。
2. **`rebuild(scene)`**：`scheduler.dispose()` → 新 `World` → `instantiateSceneState`（实例化 + 发布 `__itbScene`）→ `resolvePlayer`（缺失则 -1）→ 新 `deps`（含新物理端口）→ 新 Scheduler → `pickSystems(createSystems(deps), loaded)` 装配 → 重建 recorder/hash → 清空 kills。renderer、UI、editor、input 均不重建。
3. **保存事件**：Vite 插件 watcher 不再发 `full-reload`，改发自定义事件 `itb:scene-changed`；客户端 `import.meta.hot.on(...)` 拉取 scene → `parseScene` → `rebuild`。解析失败保留旧世界并写 `dataStatus`。
4. **编辑器状态保留**：编辑器组件不卸载；保存后 `reload()` 只重读文档，场景树/选中/页签保持。`__itbApplyScene(raw)` 暴露同一应用函数供调试/后续工具调用。
5. **控件解耦**：`ControlsDeps.world/player` 改为 getter，重建后存档/读档仍指向当前世界。
6. **渲染表抽取**：`renderTable` 移到 `apps/game/src/render-table.ts`，接收 world/alpha/previous/context，主循环不再持有渲染细节（也释放 main 行预算）。

## 验收

- 浏览器（`?editor=1`）：设置 `window.__liveMarker='alive'`，删除 player 并保存 → 页面未刷新（marker 仍在）、编辑器仍打开、`__itbScene={nodes:3, player:null, spawned:{spawner:64}}`、HUD `player missing`。
- 恢复 scene 文件 → watcher 事件 → 同一页面内 player 恢复、`nodes=4`、HUD `player ok`。
- 全量门禁 PASS。

## 后果

- 正面：编辑-应用闭环不再刷新；失败保留旧世界；渲染器/UI 不重建，热路径开销只在重建瞬间。
- 代价：重建会重置 tick 之外的运行时状态（recorder/kills/物理），属于「重开一局」语义；旧的 `bus` 订阅仍存活，系统重建时需注意 listener 重复（当前 hit listener 只加一次）。
- 回退：`rebuild` 不被调用时行为与 D2 一致；必要时可恢复 full-reload。
