# ADR-060：新增「验收记录」空间与测试方法手册

- 日期：2026-10-26
- 状态：已采纳
- 变更级别：SOFT（新增文档入口；同时改保护路径 `tools/checks/docs-map.mjs`，已用 `ALLOW_PROTECTED=1` 过门禁）

## 背景

工作流规定了证据分层 L0–L4，但 L4（人的判断）此前没有固定载体：
迭代记录只写「待验收」，没有可重复的问题表；机器测试也散在各处，没有一页能回答「现在怎么测、当前读数是多少」。
结果是每次验收都靠临场提问，跨轮次不可比较。

## 决定

1. 新增顶层空间 `工程文档/验收记录/`：
   - `README.md`：命名与规则（只记录人的观察，不抄机器读数；结论只允许通过/需重做/中止）。
   - `验收-001-002-首轮.md`：3 轮 × 10 分钟的固定问题表，覆盖辐能理解、过载归因、三槽使用、排散循环、节奏/可读性/控制感。
2. 新增 `工程文档/系统维护/测试方法.md`：L0–L4 的命令、判定与当前读数（含 L3 点名规则）。
3. `docs-map` 门禁增加 3 个必检入口，并校验 `验收-NNN[-NNN]-<主题>.md` 命名；入口总数 21 → 24。
4. 单一事实：人的结论只在验收记录；机器读数只在测试方法/门禁报告；迭代记录只留状态与指针。

## 后果

- 每次「待验收」必须指向一张表；没有表就不能声称进入验收。
- 验收表可跨迭代复用（复制改名），问题项可迭代，但结论字段稳定。
- 测试方法页需要随门禁步骤变化同步；漏更新会被 docs-map 之外的人工评审发现。
