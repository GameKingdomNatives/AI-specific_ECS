# ADR-042 本地分支护栏（本地优先）

- 状态：已接受
- 日期：2026-10-24
- 相关：`docs/proposals/005-阶段-0-落地规划.md`、Batch 0.1

## 背景

用户要求先本地建立分支保护，等稳定后再考虑 CI/公开/npm。GitHub Free 私有库的 branch protection/rulesets 返回 `403 Upgrade to GitHub Pro or make this repository public`，不能伪称已在远端开启。

## 决策

1. **本地护栏**（不是安全边界）：
   - `pre-commit` 跑 `gate --fast`；
   - `pre-push` 跑全量 gate，校验当前 HEAD 的 `.gate/stamps/<head>.json`；
   - 拒绝直接 push `main`，除非 `ALLOW_MAIN_PUSH=1`（仅 `safe-merge` 内部使用）；
   - 距上次深检 ≥5 个提交且当前 HEAD 无 `deep-<head>` stamp 时拒绝推送（Batch 0.2 接入深检）。
2. **唯一推荐合并路径**：`npm run merge:local`（feature → main，ff-only + 全量 gate + 带标记 push）。
3. **诚实声明**：`git push --no-verify` 可以绕过 hook；夜间审计扫描缺失 stamp 的提交并报告。真正的强制等 GitHub Pro/公开 + required checks。
4. **不修改远端设置**；私有库仅作备份，main 已推送。

## 验收

- `npm run hooks:test` 5 组通过：解析、直推 main、feature 允许、缺少 stamp、深检阈值。
- 实际 `git push` 直推 main 被拒；feature push 全量 gate 通过。
- 旧 tree/无 stamp push 被拒。
- 第 5 个提交无深检被拒（Batch 0.2 深检落地后补实际演练）。
- 全量门禁 PASS。

## 边界

- 不是防恶意/防强推的安全机制；本地管理员总能绕过。
- 不处理删除远端分支/标签的特殊 push；后续需要再补规则。
- `safe-merge` 会跑两次全量 gate（合并前 + push 时），换取“本地 main 不会先合入未过门禁的提交”。
