# ADR-057 · 游戏内容层的落位与门禁泛化

- 状态：已采纳（2026-10-25，随任务「推进游戏进度」由 Lead 执行，待人复核）
- 关联：`AGENTS.md`、`docs/00-最终指令.md` §2/§14、`docs/proposals/004-引擎下一阶段规划.md`

## 背景

仓库此前只有**引擎**一条产品线：`packages/engine` + 测试夹具 `packages/fixture`，`apps/game` 被当作「集成样例」，只有 `demo.scene.json` 一个场景。用户明确：引擎与游戏是**两个平级项目**，本会话要推进游戏侧，并用反馈反哺引擎。

但工程内核此前是**按一个样例硬编码**的：

- `tools/gate.mjs` 的测试根只有 `packages/engine/dist/tests` 与 `packages/fixture/dist/tests`；
- `tools/checks/capabilities.mjs` 只校验 `apps/game/scenes/demo.scene.json`，并要求每个能力条目必须出现在该场景；
- `tools/checks/system-structure.mjs` 只扫 `packages/fixture/src`；
- `tools/checks/registry.mjs` 的「系统文件必须有契约测试」只覆盖 fixture。

结论：**真正的游戏内容无法在不变成「假注册」的前提下进门禁**——这是一条必须反哺给引擎的反馈。

## 决策

1. 游戏内容放在 **`apps/game/src/game/**`**（应用层），不新建 workspace 包：游戏是产品，引擎是库；新增包要把 tsconfig 引用、导出面、包元数据一起改，成本高于本轮收益。
2. 门禁做**最小泛化**，而不是给游戏开后门：
   - 测试根加 `apps/game/dist-ts/tests`（应用 tsconfig 已含 tests）；
   - 能力校验遍历 `apps/game/scenes/*.scene.json`，每条能力只需出现在至少一个场景；
   - 结构变更扫描加 `apps/game/src/game`（递归）；
   - 契约测试检查加 `apps/game/src/game/systems` 与 `apps/game/tests`。
3. 首个游戏切片按《三段走式工程文档》第一段的最小可玩版本实现：辐能状态机 + 主炮 + 1 敌机 + 辐能条 HUD；三武器槽与复盘时间轴留到下一增量。
4. 游戏场景与夹具场景并存：默认仍 `demo.scene.json`，游戏用 `?scene=flux-core.scene.json`。等游戏侧稳定后再翻默认值，避免一次改两件事。

## 后果

- 正面：游戏内容进入与夹具同一条证据链（能力表、系统卡、契约测试、覆盖率、结构检查）；`tools/` 只做了泛化，没有降低任何阈值。
- 代价：`tsconfig`、`gate.mjs`、三个 check 脚本属保护路径，本次以 `ALLOW_PROTECTED=1` 跑门禁并在本 ADR 记录；阈值、规则强度均未变化。
- 待办：`docs/game/引擎反馈.md` 记录了本轮因游戏侧暴露的引擎缺口（标准变换组件、门禁单场景假设等），后续逐条评估。

## 附注二（同轮，2026-10-25）：人已追认 + 包体边界核查

- 用户 2026-10-25 追认本 ADR：游戏内容**自然应当分离**，且**不得进入引擎包体**；如历史上曾把游戏内容打进过引擎产物，应删除并重建。核查结果：`package-surface` 与 `pack-smoke` 均 PASS，引擎 tarball 只含 `dist/src` + `docs`（中英）+ `README.md`，`apps/game` 与 `packages/fixture` 从未进入包体；**无需重建仓库**。仓库本身作为「一个容器、两个平级项目」保留游戏源码，符合用户口径。
- 范围口径已改写：AGENTS.md 顶部与 `docs/00-最终指令.md` v1.3 修订，把「只做引擎」更新为「在框架上推进游戏、以游戏反哺引擎」。
- 迭代与证据规则见 `docs/workflow/迭代流程.md`。

## 附注（同轮，2026-10-25）：三处检查的管道子进程回归

跑全量门禁时 `mcp-smoke` / `package-surface` / `pack-smoke` 假失败，根因是 `spawnSync(..., { encoding: 'utf8' })` 走管道（沙箱 EPERM/EINVAL），且本机 `npm` 解析到 Node 22 shim。按仓库既有「文件重定向代替管道」的约定修复：

- 新增 `tools/checks/spawn-capture.mjs`：stdin/out/err 全为真实文件描述符；
- 三个检查改用 `capture(...)`，npm 调用走 `shell: true` + `npm.cmd`；
- 未降低任何检查强度，失败条件不变。

这也是一次真实的反哺：限制不是写在这份文档里的传闻，而是被游戏侧跑门禁时撞出来的。
