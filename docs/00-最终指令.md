## 0. 一句话目标

为一款俯视角机甲弹幕射击游戏（Shoot 'em up，STG）建立**自研 ECS 内核 + 现成开源组件**的简易引擎技术基础：AI 可以自由写实现，但写不坏边界；每一处质量下滑都会被机器拦住，且拦不住时能被发现。

**非目标（本轮明确不做）**：辐能／武器／僚机／敌机 AI／弹幕数据／关卡／肉鸽／美术／剧情／mod 加载器／联机／编辑器／存档格式／移动端／桌面打包。

## 2. 仓库与包结构

```
深入战火/
├─ pnpm-workspace.yaml
├─ AGENTS.md                      # 项目宪法（AI 每轮必读）
├─ packages/engine/               # 引擎本体，禁止 import 任何游戏内容
│  ├─ src/core/                   # World / Entity / 组件存储 / Query / Scheduler / CommandBuffer
│  ├─ src/ports/                  # 9 个端口接口——唯一对外契约
│  ├─ src/impl/                   # 端口实现（pixi 渲染、自研物理、输入、音频、日志）
│  ├─ src/data/                   # schema、加载器、校验、隔离
│  ├─ src/determinism/            # 随机流、输入快照、世界哈希、录制回放、无头运行器
│  ├─ src/hotreload/              # 系统替换边界、生命周期、熔断
│  ├─ src/diagnostics/            # 性能探针、诊断 dump、探针页数据源
│  ├─ src/demo/                   # 技术夹具（方块演示，非游戏内容）
│  └─ tests/                      # 单元 / 契约 / 集成
├─ apps/game/                     # 应用外壳：入口、组合根（DI 装配）、页面
├─ content/                       # 数据文件（本轮只有 schema 样例，无游戏内容）
├─ tools/                         # 门禁脚本、基准脚本、端口冻结哈希（保护路径）
├─ .githooks/                     # 版本化的 Git 钩子（保护路径）
├─ artifacts/gate/                # 门禁报告产物（不入库，仅本地留证）
├─ docs/                          # 指令、架构、系统卡、操作指南、架构决策记录（ADR）
└─ .github/workflows/gate.yml     # 可选：本地门禁的等价远端版本
```

**包边界是硬隔离**：`apps/game` 可依赖 `packages/engine`，反向禁止；`packages/engine` 的 `package.json` 用 `exports` 只暴露 `ports`、`core` 公共 API、`data` 加载器。

## 3. 分层与依赖方向

```
core（内核：无外部依赖，不 import impl / data / diagnostics）
  ↑
ports（纯接口，零实现）
  ↑
impl（实现端口）
  ↑
app（apps/game：组合根，唯一知道「谁实现谁」的地方）
```

规则（门禁强制）：

1. `core` 不得 import `ports`、`impl`、`data`、`apps`。
2. `ports` 不得 import 任何实现或第三方库（只允许纯类型）。
3. `impl` 可依赖 `ports` 与同类第三方库，**不得**依赖 `apps/game`。
4. 系统（systems）只能依赖 `core` 的公共 API 与 `ports`，禁止 import 具体实现。
5. 反向引用一次即提交失败，无豁免名单。

## 4. ECS 内核规格

| 部件 | 规格 |
|---|---|
| 实体 | 32 位 id + generation 计数；销毁后 generation 自增，旧 id 访问返回「已失效」而非静默复用 |
| 组件存储 | **SparseSet + SoA**：每组件类型一条稠密数组（TypedArray 优先）+ 稀疏索引；增删 O(1)，迭代只走稠密段 |
| 查询 | `Query<Read<A>, Write<B>>` 泛型，返回迭代器；**禁止在迭代中结构性增删**，结构变更一律走命令缓冲 |
| 访问声明 | 每个系统注册时声明 `reads: ComponentType[]` 与 `writes: ComponentType[]`；调度器启动前做冲突校验 |
| 调度 | **依赖图**：系统声明 `after/before`，调度器拓扑排序 + 环检测；**未声明的关系一律拒绝**（不允许注册顺序兜底） |
| 阶段 | input → ai → movement → collision → damage → cleanup → renderSync；每个阶段末统一 flush 命令缓冲 |
| 命令缓冲 | `spawn / destroy / addComponent / removeComponent / setField / emit`；阶段末按提交顺序执行，顺序即确定性一部分 |
| 所有权 | 声明之外的写入在 dev 期由只读代理拦截并抛错（生产期编译关掉代理） |

## 5. 事件总线规格

- **唯一跨模块通信机制**；热路径（每帧上千次）走组件数据 + 命令缓冲，**不**走总线。
- 事件是**纯数据**，不含引用、函数、类实例。
- 两档派发：
  - 同步即时：帧内必须立刻响应（命中反馈、相机抖动）。
  - 延迟队列：阶段末或帧末统一派发（界面、音频、复盘、成就）。
- **确定性顺序**：同一档内严格按发布顺序派发；事件 id 单调递增，回放时按 id 校验。
- 录制钩子：总线可开启录制，输出 `{tick, eventId, type, payload}` 序列。
- 类型安全：事件类型 → payload 类型的映射表，发送与订阅两侧都受类型约束。

## 6. 端口清单（冻结 9 个）

| 端口 | 职责 | 本轮实现 |
|---|---|---|
| `IRenderer` | 接收渲染表、管理图元与层、相机与逻辑分辨率、文本缓存 | Pixi 实现 |
| `IInput` | 每 tick 采样输入快照（键位、指针、手柄预留） | 浏览器实现 |
| `IAudio` | 播放／停止／音量 | 桩实现 |
| `IPhysics` | 形状注册、重叠查询、射线查询、接触对输出 | 自研实现 |
| `IEventBus` | 发布／订阅／录制 | 自研实现 |
| `IClock` | 固定步长、tick 号、变速与暂停 | 自研实现 |
| `IRandom` | 种子与分流随机流 | 自研实现 |
| `ILogger` | 分级日志、上下文注入（tick／系统／实体） | 自研实现 |
| `IStorage` | 键值读写（存档预留） | 桩：内存实现 |

附加占位（不计入 9 个）：`IModHost` —— 空接口，只有注释说明未来接沙箱，不实现。

**冻结机制**：`tools/port-contract.json` 保存每个端口的方法签名哈希；签名变化即门禁失败，必须走 HARD 审批并同步更新哈希与文档。

## 7. 渲染规格

- 系统**不接触** Pixi 对象，只提交渲染指令。
- 帧末提交一张 **SoA 渲染表**：`id / x / y / rot / sx / sy / anchor / frame / layer / tint / alpha / visible`。
- 渲染器做 diff（新增、销毁、变换脏标记），把连续同类图元塞进 Pixi 批处理。
- 图层：`background / world / effects / bullets / units / overlay / debug`，层顺序常量集中定义。
- 相机：世界坐标 → 屏幕；抖动与缩放；逻辑分辨率 1920×1080，等比缩放 + 黑边。
- 文本：Pixi 内 Canvas 纹理缓存，**不使用 DOM 覆盖层**（调试面板除外）。
- 图元：占位图形由代码程序化生成（矩形、圆、多边形），不引入外部美术资源。

---

## 8. 物理规格（自研查询层）

- 形状：圆、AABB（Axis-Aligned Bounding Box，轴对齐包围盒）、凸多边形（SAT，Separating Axis Theorem 分离轴定理）、线段射线。
- 空间索引：均匀网格哈希，单元格尺寸可配；宽相 → 窄相两段。
- 输出：接触对与射线命中结果**以事件形式回灌**，不在物理内部改实体。
- 物理**不持有**实体真值：位置从 Transform 组件读，结果写回走命令缓冲。
- 明确不做：受力的刚体求解、关节、CCD（Continuous Collision Detection，连续碰撞检测）、凹多边形（先拆成凸包）。

---

## 9. 确定性规格

| 项 | 规格 |
|---|---|
| 步长 | 固定 60 步／秒；渲染插值；支持暂停、单步、变速（逻辑步长恒定） |
| 输入 | 每 tick 采样一次快照，输入日志与 tick 绑定 |
| 随机 | 单一种子；每系统独立流（流 id = 系统名哈希），互不污染 |
| 世界哈希 | 每 N tick（默认 60）对实体／组件计算稳定哈希，算法固定 |
| 录制 | `{seed, inputLog, tickCount, configHash}`，压缩存储 |
| 回放 | 无头运行器重算，逐段比对哈希；失配即定位到首个偏离 tick |
| 脏局规则 | 系统崩溃被禁用 ⇒ 该局标记 invalid，停止录制，不进入哈希回归 |

## 10. 数据层规格

- 格式：JSON（JavaScript Object Notation，JS 对象表示法）+ Zod schema；schema 即契约，类型由 schema 推导。
- 每个数据文件带 `$schemaVersion`；版本不匹配即拒绝加载并给出迁移提示。
- 加载策略：启动时全量校验；单条失败 → 隔离该条 + 汇总错误清单，**不整局崩**。
- 开发期监听数据文件变更，热加载；热加载失败回滚到上一版可用数据。
- 本轮内容：只提供 schema 样例与一份空数据样例，**不写任何游戏数据**。

---

## 11. 热重载与故障隔离

- 系统以**工厂函数**形态注册：`createXxxSystem(deps) => { update(ctx), dispose?() }`。
- HMR 边界设在系统注册表模块：模块更新 → 调旧实例 `dispose()` → 建新实例 → 保留世界状态（组件数据不动）。
- 状态不可迁移的情况（组件 schema 变更）→ 明确降级为整页重载，并打印原因。
- 单系统故障：每 tick 调用包在隔离边界内；连续 3 次抛错即熔断禁用该系统，记录 `{system, tick, error, stack, recentCommands}`，其余系统继续。
- 每次崩溃写一份诊断 dump 到 `diagnostics/`，可被回放器直接载入。

---

## 12. 可视化与调试

- 每个系统可在注册表声明 `debugView`：自绘叠加层（碰撞体、查询格子、AI 意图、辐能预留）。
- 调试叠加层由 `IRenderer.debug` 通道绘制，不进正式渲染表。
- **系统探针页**：`apps/game` 提供 `?probe=<system>` 入口，只跑该系统 + 最小世界，用于单系统可视化与排查。
- 性能探针：每系统 tick 计时（环形缓冲）、帧耗时、实体数、命令数；超预算即告警。
- 基准脚本：`pnpm bench` 输出 JSON，阈值写死在 `tools/bench-baseline.json`。

## 13. 性能目标

1080p、60 帧、同屏 3000 子弹、**逻辑帧 ≤ 4ms**、单帧渲染提交 ≤ 1ms。

基准场景由技术夹具提供（方块 + 3000 个纯几何体），不含游戏内容。

## 14. 门禁清单（检查什么）

提交前必须全部通过（`pnpm gate`）：

1. `tsc --noEmit`：严格档全开，含 `noUncheckedIndexedAccess`、`exactOptionalPropertyTypes`；**零 `any`**（`unknown` + 收窄可以）。
2. `eslint`：含 `no-restricted-imports`（分层方向）、`max-lines`、`max-lines-per-function`、`complexity`。
3. `dependency-cruiser`：分层方向 + 包边界。
4. 自定义校验脚本：
   - 系统注册表完整性（每个系统都有 reads/writes 声明与依赖声明）；
   - 端口冻结哈希比对；
   - 文件 ≤ 300 行、函数 ≤ 50 行、圈复杂度 ≤ 10；
   - 每个系统至少 1 个契约测试存在。
5. `vitest run`：单元 + 契约 + 集成全绿。
6. `pnpm bench`；`pnpm gate:replay`：基准场景哈希与历史一致。

## 15. 执行策略：门禁怎么被真的执行

> 规则写在文档里不等于会被执行。本节规定：**谁在什么时候跑、绕过会发生什么、怎么证明它没被绕过。**

### 15.1 四个执行点

| 执行点 | 触发 | 命令 | 性质 |
|---|---|---|---|
| 保存期 | 文件保存 | `pnpm gate:watch` | 即时反馈，**不权威** |
| 提交期 | `git commit` | `.githooks/pre-commit` → `pnpm gate:fast` | 拦截（目标 ≤20s） |
| 推送期 | `git push` | `.githooks/pre-push` → `pnpm gate` | **权威判定（全量）** |
| 交付期 | 批次完成 | 人工读报告 + HARD 审批 + 打 tag | 人工裁定 |

- `gate:fast` = 增量类型检查 + 变更文件 lint + 全量依赖边界 + 受影响单测。
- `gate` = 全量类型检查 + 全量 lint + 依赖边界 + 自定义校验 + `vitest run` + `bench` + `replay`。

### 15.2 钩子必须版本化

- 一次性执行 `git config core.hooksPath .githooks`，`.githooks/` 入仓。
- **不使用 `.git/hooks`**：它不进版本库，会漂移、会被覆盖、无法审计。
- `pnpm setup` 负责：装依赖、设 hooksPath、校验 Node／pnpm 版本、建 `artifacts/gate/`。
- 新会话（含 AI）第一步固定是 `pnpm setup && pnpm gate:status`。

### 15.3 单一权威入口

- 本地与（未来）远端跑**同一个** `pnpm gate`，不存在「本地松、线上严」。
- 通过 = 退出码 0；任一项失败即非 0。**没有「警告通过」这种状态。**
- 每次运行产出 `artifacts/gate/<HEAD7>-<utc>/report.json` 与 `report.md`：逐条命令、退出码、耗时、Node／pnpm 版本、HEAD、工作区脏状态、waiver 清单。

### 15.4 防绕过（四道，按重要性排序）

1. **stamp 链**：`pnpm gate` 成功后写 `.gate/stamp-<tree-hash>.json`。`pre-push` 逐个检查待推送提交的树是否带 stamp，缺失即拒绝推送。→ `--no-verify` 能跳过本地提交钩子，但跳不过推送时的校验；**绕过的人交付不出去**。
2. **保护路径**：`tools/`、`.githooks/`、`AGENTS.md`、`eslint.config.*`、`tsconfig*.json`、`dependency-cruiser.*`、`vitest.config.*`、`package.json` 的 scripts 段。改动即触发 `gate:protected`：需交互确认并写 ADR，否则拒绝提交。理由：**AI 最省力的「通过」方式是把门禁改松，而不是把代码写对。**
3. **禁用标记扫描**：全仓扫描 `test.skip`／`.only`／`test.todo`／`@ts-ignore`／没有规则名的 `eslint-disable`／`--no-verify` 字样，命中即失败。
4. **测试数量回归**：`.gate/test-count.json` 记录每个系统的用例数；数量减少即失败（删测试必须同提交写明理由并走 HARD）。

**诚实说明**：Git 的 `--no-verify` 是设计允许的，本地物理阻止做不到，也不该假装做得到。策略是**检测 + 拒绝交付**，不是物理禁止。

### 15.5 例外机制（唯一合法的松口方式）

- `tools/waivers.json`：`{rule, path, reason, expiresOn, approvedBy}`。
- 报告中单列 waiver；**过期即失败**；同时存在超过 5 条即升级为 HARD。
- 除 waiver 外没有第二种松口：改阈值属于保护路径、删测试属于数量回归、删检查属于禁用标记扫描——三条路都被堵死。

### 15.6 Git 工作流

- `main` 恒绿：任何时刻检出 main 都能 `pnpm dev`。
- 分支：`feat/<批次>-<主题>`、`fix/<主题>`、`chore/<主题>`；一分支一主题。
- 提交信息：Conventional Commits（如 `feat(engine/core): 稀疏集组件存储`）；正文必含三行——**动机／改动／证据**（证据 = gate report 路径）。
- 合并：squash 进 main，保持线性历史可二分；squash 前必须全量 gate 通过。
- `main` 禁止 force push；回滚用 `git revert` 后重跑门禁。
- 批次交付打 tag：`v0.1.0-engine-core`、`v0.2.0-render-physics`、`v0.3.0-determinism`；tag 只能打在「全量 gate 通过」的提交上。

### 15.7 每轮会话的固定动作（AI 侧，不可省）

1. 开始：`pnpm gate:status` —— 报 HEAD、未提交改动、上次 gate 结果与时间。
2. 结束：`pnpm gate`，把 `report.md` 摘要（通过项、耗时、关键读数变化）贴进回复，并更新 `docs/handoff.md`。
3. **没跑过 gate 不许声称完成**；报告缺失即视为未交付。这条对 AI 比对人有约束力。

### 15.8 环境一致性

- `package.json` 的 `packageManager` 固定 pnpm 版本；`.nvmrc` 固定 Node 大版本。
- `pnpm-lock.yaml` 入库；gate 内使用 `--frozen-lockfile`。
- 本机事实：npm 缓存必须落工作区内（`--cache .npm-cache`），否则沙箱拒绝；写进 `pnpm setup`，不靠记忆。

### 15.9 长期不恶化的证据

- `docs/quality-log.md` 每批一行：测试数、契约测试数、逻辑帧耗时、gate 耗时、waiver 数、源文件数。
- 任一指标连续两批恶化 → 触发复盘并写 ADR。这是「不低于某条水平线」从口号变成趋势线的地方。

### 15.10 门禁自身也要被验证

- 每次批次交付前做一次**违规演练**：临时制造越界 import、删一个测试、改一次阈值，确认三者都被拦住，记录到 `docs/adr/005-gate-selftest.md`。
- 门禁自检是验收项：**没被演练过的门禁，等于没有门禁。**

## 16. 治理面板（人机界面）

> §14 规定检查什么，§15 规定谁来执行，本节规定**人从哪里看、从哪里动手**。面板是只读视图，不是第二套状态。

### 16.1 形态与理由

| 项 | 选择 | 理由 |
|---|---|---|
| 数据采集 | `tools/panel/collect.sh`，由 **Git Bash** 运行 | 本机沙箱禁止 Node 起管道子进程；Git Bash 是现成、稳定、零额外依赖的事实来源 |
| 数据形态 | `artifacts/panel/snapshot.js`（`window.PANEL_SNAPSHOT = {...}`） | 内联成 JS 才能双击直接打开，不起服务器、不受 `file://` 的跨域限制 |
| 渲染 | `tools/panel/panel.html` 单文件、原生 JS、零构建 | 面板本身不产生维护负担，也不引入前端框架 |
| 刷新 | `pnpm panel` = `bash tools/panel/collect.sh` 后打开页面 | 一个命令完成采集与查看 |
| 写操作 | **不放进网页**，网页只显示可复制的 Git Bash 命令 | 避免第二套状态源，也避免网页承担危险操作 |

### 16.2 面板上必须有的六块

| 区块 | 内容 | 数据来源（可复算） |
|---|---|---|
| 状态条 | 分支、HEAD、未提交文件数、领先／落后远端 | `git status --porcelain=v2 -b` |
| 门禁明细 | 最近一次 gate 的每条检查、耗时、失败摘要、是否对应当前 HEAD | `artifacts/gate/*/report.json` |
| 诊断明细 | **文件:行:列**、规则 id、原始代码片段（带行号）、**规则定义位置**（配置文件的第几行） | `artifacts/gate/*/findings.json` |
| stamp 链 | 待推送提交是否全部带 stamp | `git rev-list` + `.gate/stamp-*` |
| 改动警示 | 受保护路径是否被改、禁用标记是否出现 | `git status --porcelain` + 路径匹配 |
| 趋势 | 测试数／契约测试数／逻辑帧 ms／gate 耗时，各一条折线 | `docs/quality-log.md` 的机器可读行 |
| 待裁定 | HARD／SOFT 待批清单、waiver 数量与到期 | 提交信息标记 + `tools/waivers.json` |

### 16.3 红线（面板不能变成什么）

1. **不能成为第二真值**：面板不存任何状态，删掉整个 `tools/panel/` 不影响门禁与交付。
2. **不能当作「完成」的证据**：完成只认 `artifacts/gate/` 的报告，面板只是它的视图。
3. **不能绕过 Git**：面板上每个数字都要能追到一条 git 命令或一个文件路径，点开即见原始输出。
4. **不能联网**：无 CDN、无外部字体、无遥测；断网可用。
5. **AI 不得为了让状态好看而改面板**：`tools/panel/` 属保护路径。

### 16.4 与引擎运行时调试面板的分工

- **运行时调试面板**（见 §12）：实体数、各系统 tick 耗时、碰撞叠层、AI 意图——回答「游戏里发生了什么」。
- **治理面板**（本节）：分支、门禁、stamp、趋势、待批——回答「这次交付能不能算数」。
- 两者不共用代码、不共用进程：前者在游戏内，后者在浏览器里读静态文件。

### 16.5 什么时候看

- 每轮会话开始：替代人肉解读 `gate:status`。
- 每次合并／打 tag 前：替代翻日志。
- 每批交付：截图或读数摘要进 `docs/handoff.md`，作为「质量未下滑」的可见证据。

### 16.6 常用命令复制（面板唯一的交互）

面板只做一件事：把「批阅之后要做什么」变成一条可粘贴的命令。点一下复制，粘到 Git Bash 执行。

| 批阅结果 | 面板给出的命令 | 副作用 |
|---|---|---|
| 通过，继续推进 | `pnpm review accept --note "<理由>"` | 追加 `docs/review-log.md`，并打印下一步（打 tag／合并） |
| 退回，要求修改 | `pnpm review reject --note "<理由>"` | 追加 `docs/review-log.md`，并打印候选回退命令 |
| 撤销某次提交 | `git revert <sha>`（面板已填好 sha） | 生成反向提交，必须重跑 gate |
| 重跑门禁 | `pnpm gate` | 产出新报告 |
| 重新采集 | `pnpm panel` | 刷新快照 |

规则：

1. `<理由>` 是**必填占位符**，复制后必须替换；`review` 脚本拒绝空理由——面板不替人写字。
2. **命令只复制、不执行**：网页不调用任何写操作，避免在 Git 之外长出第二份事实。
3. 每次 accept／reject 落一行到 `docs/review-log.md`：时间、分支、HEAD、结论、理由——**批阅本身也要可审计**。
4. 退回不自动撤提交：是否 revert、撤到哪个提交由人决定，面板只把候选命令算好。

## 19. 验收标准

- 治理面板用 `pnpm panel` 打得开，六块数据齐全、断网可用，且每个数字都能追到一条 git 命令或一个文件。
- `pnpm gate` 全绿（首次提交前）。
- `pnpm dev` 起得来，技术夹具在屏幕上运动、碰撞、渲染正确。

- 3000 个几何体场景下逻辑帧 ≤ 4ms（本机实测数字写进报告）。
- 删掉 `apps/game` 后 `packages/engine` 仍可独立构建与测试。
- **违规演练通过**：越界 import、删测试、改阈值三种绕过全部被拦。

## 22. UI 层与可视化编辑（Onlook）—— 待裁定

### 22.1 事实边界（2026-10-20 核查）

Onlook 是面向 React／Next.js 的可视化编辑器：在无限画布上直接编辑真实组件，改动写回仓库里的 TypeScript；读取 Tailwind 配置与 shadcn/ui，官方亦列出 Vite 项目支持；通过 GitHub 授权读取项目，用 Storybook（没有则脚手架）把组件放上画布（来源：<https://www.onlook.com/for/nextjs>、<https://github.com/onlook-dev/onlook>）。

**关键限制：它编辑 DOM／React 组件，不编辑 canvas 绘制。** 战场由 Pixi 直接画进 canvas，所以 Onlook 能编辑的是菜单、战前配置、HUD 覆盖层、设置页、复盘时间轴——**不是子弹与机甲本身**。

### 22.2 分层结论

- **战场表现**：Pixi canvas（引擎渲染层，维持现状）。
- **UI**：新增 DOM 层，React + Tailwind，叠在 canvas 之上，目录 `apps/game/src/ui/**`。
- **数据方向**：引擎每帧（或降频）产出只读 `UiSnapshot`（纯数据，不含 Pixi 对象），React 用 `useSyncExternalStore` 订阅；UI 只发意图命令（`startRun`、`setVolume`），不得直接改世界。
- **确定性**：DOM 属冷路径，不参与逻辑 tick；快照可 10Hz 降频，避免每帧调度 React。
- **治理**：Onlook 也是代码作者 ⇒ 其改动必须过同一门禁；引擎、端口、门禁脚本对它只读。

### 22.3 工具链冲突

Onlook 需要可运行的 React 开发服务器（Vite／Next.js）。本机沙箱内 Vite 不可用（esbuild 子进程被拒，见 ADR-001），因此**可视化编辑必须在你的终端或 Onlook 云端进行**；本地门禁仍可在沙箱内跑。若引入 Vite：`apps/game` 加 devDependency，UI 单独 tsconfig，并新增「UI 不得 import core／impl」的依赖规则。

### 22.4 待裁定（四项）

1. UI 层是否确定为 React + Tailwind（DOM 覆盖层），战场继续留在 Pixi canvas？
2. 是否接受 Storybook 依赖（Onlook 组件画布的载体）？
3. Onlook 用云端还是自托管（仓库开源，云端需账号与定价）？
4. 接入时机：第二批（渲染层落地后），还是等第一条真实 UI 出现后？

### 22.5 不建议的做法

- 把战场搬进 DOM（性能与批渲染都会崩）。
- 让 Onlook 直接改 `packages/engine/**`（绕过端口冻结与确定性约束）。
- 为 Onlook 单独维护一套组件副本（立刻出现第二真值源）。
