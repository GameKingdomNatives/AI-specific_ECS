## 经验教训

### 编码/工具

- Windows PowerShell 5.1 的 `Get-Content -Raw` + `Set-Content` 组合会破坏 UTF-8 中文；批量替换必须用 `[IO.File]::ReadAllText/WriteAllText` 或编辑工具。
- `Set-Content -Encoding utf8` 可能写入 BOM；`package.json` 带 BOM 会让 Vite/PostCSS 的 JSON.parse 直接失败。
- 批量 `git add -A` 会把 `.archify/` 等生成物加入暂存/触发 gitfacts；必须显式 add。
- 包重命名后，`pack-smoke` 的 `node_modules/@itb/engine` 路径和 tar 目标要同步，否则解包 ENOENT。

### npm/发布

- 恢复码不是日常 2FA：使用 recovery code 会触发 72h 冻结，发布暂停；不要用恢复码反复试。
- `stage approve` 只支持 OTP；WebAuthn/passkey 是交互式 `npm publish` 的路径。
- TOTP 必须来自 npm 的 `otpauth` 密钥；Microsoft 账户登录不等于 npm TOTP 条目。
- npmjs 在中国大陆可能 TCP 超时；GitHub 正常不等于 registry 可用。先 `npm ping`，再配自己的代理/VPN。
- 首包后配置 OIDC trusted publishing，减少后续 2FA 依赖。

### 文档/工程

- 发布文档必须同时写“为什么/怎么创建/机制/生命周期/前后端边界”，否则其他 Agent 只能看到 API 列表。
- 文档总集要放在可发现位置（根 README + docs/README），并说明“原型、不建议生产”。
- 文档必须与当前状态同步：staged ≠ published；私有 ≠ 公开；恢复码 ≠ 可日常使用。
