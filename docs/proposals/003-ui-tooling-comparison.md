# 提案 003 · UI 工具横向对比：Storybook / Onlook / Figma / Webstudio

- 日期：2026-10-21
- 状态：供决策（关联 ADR-002、ADR-009）
- 目的：判断设计侧是否必须引入 Onlook，以及各方案的接入与长期代价

## 0. 先厘清角色关系

| 工具 | 角色 | 能否写回代码 |
|---|---|---|
| Storybook | 组件陈列室 + 状态验收面（每个 props 组合一个 story） | ❌ 只读渲染 |
| Onlook | 在运行中的组件画布上拖拽编辑，写回 TSX/Tailwind | ✅ 写回源码 |
| Figma | 设计源文件与协作 | ❌（Dev Mode 可给标注/上下文，插件可导出代码） |
| Webstudio | 可视化建站，产出真实 HTML/CSS | ✅（产出的是站点，不是组件库） |

关键事实：Onlook 的画布来源可以是 Storybook（ADR-002 核查时确认）。**所以 Storybook 不是 Onlook 的替代品，而是它的前置**；先有 story，Onlook 才能把组件放上画布。Storybook 的投入不会因为引入 Onlook 而作废。

## 1. 横向对比

| 维度 | Storybook | Onlook（自托管 Web） | Onlook（桌面 v0.2.32） | Figma + Dev Mode | Webstudio |
|---|---|---|---|---|---|
| 设计师能否直接改 | 只看，不能改 | 能拖拽/改属性 | 能（若支持本地项目，待实测） | 能改设计稿，不直接改代码 | 能 |
| 设计师要装什么 | 浏览器 | Bun + Supabase CLI + Docker + 后端迁移 | 一个安装包 | 浏览器/Figma 桌面版 | 自托管一套服务 |
| 开发接入成本 | 每状态 ~15–20 行 story；已接入，门禁含构建 | 小时级：环境、密钥、迁移、版本对齐 | 分钟级安装；能力未知 | 低：设计给标注，开发实现 | 中：新栈、部署、与现有组件库并存 |
| 长期维护成本 | 低：随组件演进的纯前端资产 | 高：CLI/镜像/迁移版本必须长期钉住 | 中：桌面版跟版本 | 低：Figma 官方维护 | 中高：自托管服务与升级 |
| 代码质量风险 | 无（不产码） | 中高：写回的代码需 review + 门禁 | 中 | 低（人工实现） | 中（产出的代码风格独立） |
| 与现有门禁契合 | 已契合（`storybook` 步骤） | 需把 Onlook 改动当普通 PR 过 gate | 同左 | 天然契合（人工提交） | 需新建部署链路 |
| 对 Figma 习惯的贴合 | 低（不是设计工具） | 中（画布像 Figma，但绑定工程环境） | 中 | **最高**（就是 Figma） | 中（自有画布） |
| 失败模式 | story 腐烂（门禁可拦） | 上游不自洽时整条链装不起来（本次已发生） | 版本旧、能力未知 | 导出的代码需重写 | 学习成本转移给设计 |

## 2. 代价的量化（本项目）

- **Storybook**：`App.stories.tsx` 49 行覆盖 3 个状态；构建约 2 秒进全量门禁；设计师零安装。
- **Onlook 自托管**：本次实测耗时数小时，卡在 4 个环节（Bun 安装、`free-email-domains` postinstall、Supabase CLI 2.53.6 拒绝全局安装、迁移 0008 的 Storage 限制），且上游 `config.toml` 引用未跟踪的函数文件。即使装成，后续每次升级都要重新对齐 CLI 与迁移。
- **Onlook 桌面版**：一个 175.9 MB 安装包；但版本停留在 2025-07，是否支持打开本地项目**尚未验证**——这是它唯一的关键不确定性。
- **Figma + Dev Mode**：设计师零额外安装；开发侧成本主要在「把标注翻译成既有组件」，与今天的手工实现成本相同；若设计方有 Dev/Full seat，Dev Mode MCP 可让 AI 直接读上下文，省掉翻译。

## 3. 结论与退让空间

1. **Storybook 必留**：它是低成本、高确定性的组件验收面，也是 Onlook 未来接入的前置。
2. **不把 Onlook 自托管作为前提**：投入产出比已被本次实测证伪；保留为「上游修好后再评估」。
3. **Figma 留在设计主路径**：贴合设计师习惯，零工程环境。
4. **可退让的三档**（按成本从低到高）：
   - 一档：Storybook 只读验收 + Figma 标注（现状 + ADR-009）。
   - 二档：加 Figma Dev Mode MCP，让 AI 读设计生成组件（需设计方 seat）。
   - 三档：Onlook 桌面版沙箱试用（只读分支，改动走 PR + 门禁）；若它支持本地项目，再考虑纳入。
5. **不做**：为设计师部署自托管 Onlook 全栈。那是把工程环境成本转嫁给不承担它的人。

## 4. 需要用户/设计方确认的事

- 设计方 Figma 席位是否含 Dev Mode（决定二档可行性）。
- 是否接受「设计改稿 → 开发实现」的异步节奏；若必须所见即所得，才进入三档。
- Onlook 桌面版是否值得花 10 分钟做一次「打开本地项目」验证。
