# 引擎侧开发教训（2026-10-20 ~ 10-21）

按「现象 → 根因 → 修法 → 证据」记录，全部来自本仓库真实提交与门禁输出。

## 1. 世界哈希的「空集陷阱」

- 现象：加入子弹后，`worldHash(world, [Position, Box, Bullet])` 恒等于 FNV 基值 `811c9dc5`，确定性校验形同虚设。
- 根因：`worldHash` 的语义是「同时拥有全部给定组件」；方块（Position+Box）与子弹（Position+Bullet）互斥，查询结果为空。
- 修法：新增 `worldHashGroups(world, [[Position, Box], [Position, Bullet]])`，既有算法不变（ADR-005）。
- 证据：`tests/determinism.test.ts`；浏览器 386 tick 录制 → CLI 重演哈希 `e6e4938c` 一致。

## 2. 子弹复用了「会反弹」的移动系统

- 现象：开火后子弹数量只增不减，实体数持续上涨。
- 根因：`demo.movement` 对所有 Position+Velocity 做边界反弹；子弹也在其中，永远不出界，回收逻辑永不触发。
- 修法：方块移动改为 `query(Position, Velocity, Box)`；子弹新增 `demo.bulletMovement`（直线、出界 despawn，`after: demo.movement`）。
- 证据：按住 0.9s 场上 4 发、松开 1.8s 归零；`tests/weapon.contract.test.ts` 覆盖。

## 3. 门禁只看退出码 → depcruise 长期空转

- 现象：`depcruise PASS`，但日志是 Usage 文本；注入越界 import 后仍 PASS。
- 根因：无参数运行只打印 Usage 并退出 0；JSON 输出模式下**有违规也退出 0**。
- 修法：`tools/checks/depcruise.mjs` 解析 `summary.violations`，解析失败即失败（ADR-007）；`tools/drill.mjs` 做注入演练。
- 证据：修复后 237 模块 0 违规；演练能拦住 `core→impl` 与 312 行超预算文件。

## 4. TypeScript 的 ESM JSON 与输出目录

- 现象：`content.ts` 导入 JSON 报 TS1543/TS6307；Vite 构建把 tsc 产物清空。
- 根因：NodeNext 要求 `with { type: 'json' }` 且 JSON 需进 tsconfig include；tsc 与 Vite 共用 `dist/`。
- 修法：导入加 `with { type: 'json' }`，include 加 `src/**/*.json`；tsc 输出改 `dist-ts/`。
- 证据：全量门禁 build PASS；`apps/game/dist-ts` 与 `dist` 分离。

## 5. 基准测量的抖动

- 现象：bench 单次测量 0.60~0.70ms，1.25 容差把正常抖动放大成红灯。
- 根因：毫秒级短任务测量方差大；单次采样不稳定。
- 修法：三次取中位数、容差 1.5、基线文件 `tools/bench-baseline.json`；门禁同时判绝对预算 4ms。
- 证据：最近读数 0.821ms（基线 0.688，容差内）；`bench` 步骤进全量门禁。

## 6. 物理桥依赖了夹具

- 现象：`bridge/physics.ts` 直接 import `demo` 的组件，桥与夹具耦合。
- 根因：先写实现后抽层，组件来源没有注入。
- 修法：`createPhysicsBridge(physics, { position, box })`，组件由调用方注入；测试改用自定义 `BridgeProbe*` 组件。
- 证据：`tests/bridge.contract.test.ts` 不再 import demo。

## 7. 存档信封的解析形状

- 现象：`dumpSink.restore()` 总是空，持久化测试失败。
- 根因：`persist()` 写的是 `{version, dumps}`，`parse()` 却按裸数组读。
- 修法：兼容两种形状，且损坏数据返回空列表而不是抛错。
- 证据：`tests/diagnostics.test.ts` 4 例。

## 8. 热加载会改变世界，录制不可跨热加载重演

- 现象：改内容 JSON 后抓的录制，在 CLI 重演哈希不一致。
- 根因：热加载销毁并重建实体，CLI 只在开局生成一次。
- 修法：录制写入 `startHash`，重演前比对；不一致时明确报「非干净开局」并拒绝（ADR 之外的守卫）。
- 证据：脏录制被 CLI 拒绝；干净录制 386 tick 哈希一致。

## 9. 规格与实现的漂移要显式记录

- 现象：端口实际是 10 个（多 `IModHost`），规格写 9 个。
- 修法：用户批准后改规格与 AGENTS 为 10，新增 ADR-006；端口哈希重新接受。
- 教训：漂移不可怕，未记录才可怕。

## 10. 依赖安装的「遗留物」比依赖本身更麻烦

- 现象：`npm install` 报 `Invalid Version` / 工作区识别失败 / EPERM。
- 根因：早期 pnpm 在 `packages/engine/node_modules` 留下 junction，npm 读取到无版本条目；运行中的 dev server 锁住原生模块。
- 修法：清理遗留 junction、停止占用进程后重装；依赖声明归位到 `apps/game`。
- 证据：清理后 `npm install` changed 150 packages、exit 0。

## 11. 夹具不是产品，边界要写进文档

- 现象：为验证管线加入的射击/命中，容易被误当游戏内容。
- 修法：`demo.*` 标注为技术夹具；正式能力（物理桥）上移 `engine/bridge`；AGENTS 明确不做机甲/辐能/僚机/关卡。

## 12. UI 工具的选型教训（详见 `经验教训-·-2026-10-UI-工具链.md`）

- 本地、免费、可商用优先；云工具与付费席位不进关键路径。
- Storybook 是验收面，不是编辑器；静态包可离线交付设计方。
