# 05 · Agent Playbook / 智能体调用手册

This is the operational playbook for another agent/session that must **discover, use, modify, and maintain** this repository.

## 1. First five minutes / 前五分钟

Read in this order:

1. `README.md` — why/how/mechanism, prototype status;
2. `contracts/agent.json` — machine-readable entrypoints/capabilities;
3. `docs/package-guide/索引.md` — this guide;
4. `docs/交接.md` — current state and handoff;
5. `docs/adr/` — decisions and traps.

Commands:

```bash
node tools/status.mjs
node tools/itb.mjs describe
node tools/itb.mjs inspect
node tools/itb.mjs impact
node tools/gate.mjs --fast
```

## 2. Task recipes / 任务配方

### “I need to use the engine”

```ts
import { createEngine } from 'agent-specific_ecs';
```

Do not import `@itb/engine`; the package was renamed. Do not copy `apps/game` into the kernel.

### “I need to add a system”

1. Read `docs/runbooks/07-如何新增系统.md`.
2. Define component with `defineComponent`.
3. Write `SystemDef` with `reads/writes/phase/update`.
4. Structural changes → `ctx.commands`.
5. Cross-system cold signal → `ctx.events`.
6. Add contract test + capability entry.
7. Run `node tools/gate.mjs --fast`, then full gate.

### “I need to change public API”

1. Check `contracts/api-surface.json` and `tools/port-contract.json`.
2. Ports/signatures are HARD: require human approval + ADR.
3. Update snapshot only after approval:
   `node tools/checks/api-surface.mjs --update` (if available).
4. Update docs + ADR + handoff.
5. Full gate, receipt, stepwise commit.

### “I need to change the export”

- `contracts/export-policy.json` is the only allowlist.
- Runtime: `packages/engine/dist/src` + `packages/engine/docs` (EN/ZH) + `README.md`.
- Dev-only: repo tools/contracts/root docs/tests/artifacts/fixture.
- `node tools/checks/export-policy.mjs`.

### “I need to publish”

- Package: `agent-specific_ecs@0.1.0`.
- npm is **not published**; staged id `ec2e8ee5-c630-40d8-bd39-8defb7544de1`.
- Account is in a 72h recovery-code hold until about **2026-10-28 00:34 +08**.
- After hold: use Microsoft Authenticator **npm TOTP** to approve staged, or an npm-registered **Edge passkey** for interactive `npm publish`.
- `npm stage approve` only accepts `--otp`; passkey is for direct interactive publish.
- After first release: configure OIDC trusted publishing (`publish.yml`) to avoid TOTP on every release.
- Never use a recovery code as a routine publishing factor: it triggers a new 72h hold.

## 3. Hard constraints / 硬约束

From `AGENTS.md` and ADRs:

- no `any`, `@ts-ignore`, unsafe assertions;
- `core` must not import ports/impl/data/demo/apps;
- ports are pure types;
- systems must not import each other;
- structural changes only through CommandBuffer;
- no EventBus on hot paths;
- no second source of truth for positions;
- do not bypass contracts or weaken sensors;
- `tools/`, `package.json`, tsconfigs, lockfile are protected; use `ALLOW_PROTECTED=1` only with approval.

## 4. Evidence discipline / 证据纪律

Every change must produce:

```text
code + test
→ fast gate
→ full gate PASS
→ receipt
→ ADR/docs/handoff update
→ commit
```

Never claim “done” from a command’s exit code alone. Parse reports:

- `artifacts/gate/<run>/report.md`
- `artifacts/receipts/<HEAD>.json`
- `artifacts/gate/<run>/findings.json`
- `artifacts/gate/<run>/depcruise.log`

## 5. Common traps / 常见坑

| Trap | Correct action |
|---|---|
| `@itb/engine` import | use `agent-specific_ecs` |
| demo in engine | import from `@itb/fixture` (private) |
| system mutates world structure | use `ctx.commands` |
| EventBus in per-frame loop | use direct data/command; EventBus is cold |
| use `Math.random` | use `core/random` streams |
| fix failing gate by deleting check | fix cause; never weaken sensors |
| npm recovery code | avoid daily use; triggers 72h hold |
| Edge passkey | must be registered to npm; PIN is local |
| package publish with BOM | no BOM in package.json; use UTF-8 no BOM |
| stage approve with passkey | use `--otp`; passkey is direct publish |

## 6. Scope discipline / 范围纪律

This repository is engine/technical foundation only. Do not add game content (mechs/levels/cards) to the kernel. Fixtures are replaceable; apps are downstream.

## 7. Handoff / 交接

Before ending a session:

1. full gate;
2. update `docs/交接.md`;
3. update this guide if public surface changed;
4. commit/push;
5. write concise memory facts (public status, package name, auth path, blockers).

## 8. When blocked / 卡住时

Distinguish:

- **code failure** → read report, fix, rerun;
- **network failure** → proxy/VPN; npm registry may be blocked in CN;
- **auth failure** → TOTP/passkey/OIDC; do not fake;
- **policy failure** → stop and ask human; do not bypass.

Report exact command, exit code, and evidence path; never claim success without it.
