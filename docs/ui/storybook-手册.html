0 · 这本书怎么用

这不是官方文档的逐字译本，而是按使用顺序重排的要点版：每一章对应官方文档的一页或几页，删掉了营销段落和框架分支（React / Vue / Angular / Svelte 的差异），只保留与本项目相关的 React 路径。官方原文链接在文末「来源」里，遇到本书没覆盖的细节以原文为准。

读法建议：先在 apps/game 下跑一次 npm run storybook，边看边读第 3–6 章；第 9 章是本项目的落位说明，读完能直接动手加一个 story。

1 · Storybook 是什么

Storybook 是一个组件工作台：它把组件的每一个「有意思的状态」单独渲染成一个页面，你不用启动整个应用、不用点到那个状态，就能看到组件长什么样、改一个参数立刻变化。

官方对「story」的定义是：A story captures the rendered state of a UI component. 一个 story 就是组件在某一组参数下的渲染快照。同一个组件可以有很多 story：正常、禁用、长文案、加载中、报错。

它解决三个具体问题

  • 状态不可见：组件在真实应用里要连点三步才出现，改一行 CSS 要重新走一遍流程。story 把它变成一次点击。
  • 边界不可枚举：长文案、空数据、极端宽度这些「很少发生」的状态没人测。story 强制你把它们写下来，写下来就永远能看。
  • 设计评审没有共同对象：讨论「这个按钮太重了」时，双方看的可能是不同页面。story 是可指认的单一坐标。

story 文件是开发期文件，不会进生产包——它只是一个记录了「怎么把组件渲染成某个状态」的 ES 模块。

2 · 安装与版本要求

官方推荐用 CLI 安装，在项目根目录执行：

npm create storybook@latest

CLI 会读项目的依赖，自动选最合适的框架配置，并在项目里生成 .storybook/（配置目录）和若干示例组件与 story。安装过程可以终止，配置会保留。

3 · 写一个 story

story 文件与被测组件放在同一个目录，文件名形如 Button.stories.tsx。一句话记住结构：默认导出描述「这是哪个组件」，具名导出描述「这个组件的某个状态」。

最小可用例子

// Button.stories.tsx
import type { Meta, StoryObj } from '@storybook/react-vite';
import { Button } from './Button';

const meta = {
  title: '基础组件/按钮',      // 左侧栏的层级，用 / 分层
  component: Button,            // 让 Controls 能自动推断 props
  args: { children: '确认' },   // 所有 story 共享的默认参数
} satisfies Meta<typeof Button>;

export default meta;
type Story = StoryObj<typeof meta>;

// 只要名字：直接复用 meta.args
export const 默认: Story = {};

// 改一个参数：在默认值上覆盖
export const 禁用: Story = { args: { disabled: true } };

// 极端内容：长文案撑开时的表现
export const 长文案: Story = {
  args: { children: '这是一段非常长的按钮文案，用来检查省略号与换行' },
};

几条会被反复用到的规则

  • title 决定侧边栏位置；基础组件/按钮 会渲染成可折叠的一级「基础组件」。
  • 导出名就是 story 名。用中文导出名在本项目里是约定：评审时读的是中文，不是 Primary。
  • args 可以在 meta 上写（共享默认值），也可以在单个 story 上写（覆盖）。story 级别的值优先。
  • satisfies Meta<typeof Button> 让 TypeScript 校验你的 story 参数真的对得上组件 props。
常见误区：story 里不要写「业务逻辑」。story 只描述状态；需要交互流程（点击后展开、异步加载）用 play 函数（官方单独一页，本书不展开）。

4 · Args：组件的输入

官方定义：Args are Storybook’s mechanism for defining those arguments in a single JavaScript object. 它把 React 的 props（Vue 的 props、Angular 的 @Input）统一收进一个对象，于是 Storybook 和它的插件可以「只改这一个对象」就把组件换成另一个状态——不需要改组件代码。

三层覆盖

// 1) 组件级默认值（meta）
const meta = { args: { size: 'md', children: '确认' } } satisfies Meta<typeof Button>;

// 2) story 级覆盖
export const 小号: Story = { args: { size: 'sm' } };

// 3) 组合：只覆盖关心的键，其余继承
export const 小号禁用: Story = { args: { size: 'sm', disabled: true } };

为什么用 args 而不是直接写 JSX

  • 可编辑：Controls 面板可以直接改 args，组件实时重渲染——这是 Storybook 最常用的一步。
  • 可复用：同一份 args 能带进文档页、交互测试、视觉回归。
  • 可序列化：args 是纯数据，才能跨 URL、跨工具传递。

和 args 配套的是 argTypes：它描述参数怎么被控制（用什么控件、有哪些选项、会不会出现在面板里），而不是参数的值。第 6 章会用到。

5 · Parameters：外挂配置

官方定义：Parameters are a set of static, named metadata about a story, typically used to control the behavior of Storybook features and addons. 一句话区分：args 是给组件的，parameters 是给 Storybook 的。

官方给的例子是背景色工具条：

export const 深色背景: Story = {
  parameters: {
    backgrounds: {
      options: { dark: { name: '深色', value: '#1a1a1a' } },
    },
  },
};

三个作用域

层级写在哪影响范围
全局.storybook/preview.ts 的 parameters所有组件、所有 story
组件级meta 上的 parameters该组件下所有 story
story 级具名导出上的 parameters只有这一个 story

parameters 是静态元数据：它不参与组件渲染，改它组件不会因为「参数变了」而重渲染。所以「这个控件有哪些选项」放 parameters，「组件现在的值是多少」放 args，两者不要混。

6 · Controls：实时改参数

Controls 是下方那块「参数面板」：它根据组件的 props 自动生成输入控件（文本框、开关、下拉、颜色……），你在面板里改一下，上面的组件立刻重渲染。不需要给组件加任何代码。

自动推断的边界

TypeScript 类型能被推断的（boolean → 开关、'a'|'b' → 下拉、string → 输入框），面板会自动生成；推断不出来的（联合类型没写全、样式对象、插槽内容），要手工补 argTypes：

const meta = {
  component: Button,
  argTypes: {
    size: { control: 'inline-radio', options: ['sm', 'md', 'lg'] },
    onClick: { action: 'clicked' },   // 在 Actions 面板里显示调用
    children: { control: 'text' },
    // 不想出现在面板里：
    className: { control: false },
  },
} satisfies Meta<typeof Button>;

几种常用 control

control适用效果
text字符串单行输入
boolean开关类勾选框
select / inline-radio有限枚举下拉 / 横排单选
range数值区间滑块（配 min/max/step）
color颜色取色器
false不需要暴露从面板隐藏
为什么值得花时间写 argTypes：它同时喂给 Controls 和 Autodocs。写一次，面板和文档页都对了；不写，面板会冒出一堆 unknown 控件，评审时没人愿意点。

7 · Autodocs：文档自动生成

Autodocs 把 story 变成活的文档页：它读取 meta 上的 args / argTypes / parameters，生成一页包含「组件说明 + 所有状态预览 + 参数表」的文档，位置在该组件的根级。

开启方式

const meta = {
  component: Button,
  tags: ['autodocs'],   // 一行开启
} satisfies Meta<typeof Button>;

也可以在 .storybook/preview.ts 里给全部组件默认开启（tags: ['autodocs']），再在单个组件上关掉。

和 MDX 的分工

  • Autodocs：structure 由 story 自动推导，适合「参数多、状态多」的组件，几乎不写文字就能有一页能看的文档。
  • MDX：手写文档（设计动机、用法禁忌、对比图），可以嵌入 story 预览。本项目暂不使用 MDX——文档正文仍写在 Markdown 里，Storybook 只负责「看组件」。

8 · 构建与发布

开发时用 storybook dev（默认 6006 端口）。要交付或部署时构建成纯静态文件：

npx storybook build -o storybook-static

产物是 storybook-static/——没有后端、没有路由依赖，任何静态服务器都能托管（内网、对象存储、GitHub Pages 均可）。构建产物里每个 story 都对应一个可直达的 URL，评审时可以直接甩链接。

命令用途本项目端口
npm run storybook组件工作台（开发）6006
npm run storybook:build构建静态产物—
npm run storybook:preview（如有）预览已构建产物7007
受限环境注意：本项目的受限会话跑不了 storybook build（子进程管道被禁）。构建属于 L3 环境受限项，不算 PASS，需要在完整会话（人的终端）里验证。

9 · 在本项目里怎么用

这一章不是官方内容，是本项目的落位约定。完整的目录地图与维护规则见 工程文档/系统维护/UI设计入口.md。

三条命令

命令打开说明
npm run devlocalhost:5173游戏本体（场景 flux-core），验收用的是它
npm run storybooklocalhost:6006组件工作台，改 UI 组件时用
npm run storybook:build—出静态产物；受限会话跳过

加一个 story 的四步

  1. 在组件同目录建 X.stories.tsx，默认导出写 title: '分组/组件名'（中文）。
  2. 至少写三个状态：正常、禁用/边界、长文案或极端尺寸。只写一个「默认」等于没写。
  3. 颜色、间距、字号只用 apps/game/src/ui/tokens.ts 里的 token，不要在 story 里写死 hex。
  4. 跑一遍 npm run storybook 确认没有渲染报错，再把 story 名和截图放进 PR 说明。

本项目已知边界

  • Storybook 的界面外壳是英文且没有官方 i18n（10.x 未提供语言包）。中文只覆盖到 story 名、组件说明与文档页内容——侧边栏按钮、面板标题仍是英文，这是预期状态，不做 hack。
  • 战场渲染（render-table.ts）不在组件库里，Storybook 里看不到游戏画面；这是有意的边界，别为了「全部进 Storybook」去拆渲染层。
  • UI 层有一条依赖规则 ui-no-engine-internals：UI 组件不得 import 引擎内部实现。写 story 时若发现必须 import 引擎内部，说明组件放错了层。
