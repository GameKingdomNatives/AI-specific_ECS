# 迭代工作流 · 本仓库版（v1.0）

> 日期：2026-10-25 · 状态：生效
> 来源：`通用资源-副本/原始协议/迭代开发工作流规范.md`、`迭代开发AI执行协议.md`、`Git工作流规范.md`、`迭代开发模板/记录模板/迭代模板.md`，按本仓库的双项目结构与门禁体系改写。
> 定位：**流程定义层**。方向见 `docs/00-最终指令.md`，护栏见 `AGENTS.md`，事实与交接见 `docs/交接.md`，趋势见 `docs/质量日志.md`。

## 0. 为什么需要它

这个仓库的质量由机器保证（门禁、回执、stamp、夜检），但**"下一步做什么、什么时候算做完、谁说了算"**此前只散落在会话与 handoff 里。本文件把那部分固定下来，让下一个会话不必重新发明流程，也不必靠人肉纪律。

## 1. 三个项目单元

| 单元 | 路径 | 性质 | 不得做的事 |
|---|---|---|---|
| 引擎 | `packages/engine` | 可被外部消费的库（npm 包 `agent-specific_ecs`） | 不得 import `apps/`；**游戏内容不得进入包体** |
| 游戏 | `apps/game` + `docs/game/` | 产品：场景、游戏系统、HUD、编辑器接线 | 不得私改引擎契约；缺口记 `docs/game/引擎反馈.md` |
| 夹具 | `packages/fixture` | 测试替身 | 不得承载游戏内容 |

工程内核（`tools/`、`contracts/`、本目录）服务于以上三者。

## 2. 迭代节奏

```
开工（status + 交接 + 门禁状态）
  → 立项（选 1–2 个目标，写迭代记录，过边界检查）
  → 执行（单点串行：目标 → 功能 → 检查点；每检查点 30min–2h）
  → 自检（证据分层，见 §4）
  → 验收（需要人感官的项交给人；可读数项由机器给）
  → 收尾（文档、质量日志、handoff、commit/tag、推送）
  → 方向校正判定（仅在触及时）
```

- 一次迭代只挑 **1–2 个目标**；贪多是迭代地狱的唯一入口。
- 一个目标拆 2–5 个功能，一个功能拆 2–4 个检查点。
- **3 轮修复上限**：同一检查点修 3 轮仍不过，停下上报，不硬磨。
- 功能完成即更新 `docs/交接.md` 与相关系统卡，不等迭代结束。
- 每次迭代一份记录：`工程文档/迭代记录/iter-NNN-<slug>.md`（模板见 `工程文档/_模板/迭代.md`）。

## 3. 文档职责（唯一真相）

| 文档 | 管什么 | 什么时候改 |
|---|---|---|
| `docs/00-最终指令.md` | 方向、范围、技术栈、门禁清单 | 范围或硬规则变化时（HARD） |
| `AGENTS.md` | 护栏：边界、权限、门禁、环境事实 | 边界或权限变化时（HARD） |
| `docs/workflow/` | 流程：怎么迭代、证据怎么算 | 流程失效时 |
| `docs/adr/` | 每个 HARD 决策的理由与代价 | 决策当时 |
| `docs/交接.md` | 事实：当前状态、本轮完成、下一步、待人裁定 | 每次收尾 |
| `docs/质量日志.md` | 趋势：测试数、覆盖率、性能、门禁结论 | 每次收尾 |
| `docs/systems/` | 每个运行中系统的职责与不变量 | 系统变化时 |
| `docs/game/` | 游戏侧：切片、操作、引擎反馈 | 游戏推进时 |
| `contracts/` | 机器可读契约（能力/规则/导出面） | 与代码同提交 |

## 4. 证据分层（不得越级）

| 级别 | 含义 | 例子 |
|---|---|---|
| L0 | 能编译 | `tsc -b` |
| L1 | 行为被断言 | 单元/契约/属性/黄金测试 |
| L2 | 门禁通过 | 全量 `node tools/gate.mjs` 退出码 0 |
| L3 | 环境受限未执行 | 沙箱禁管道子进程导致 build/storybook/starter 未跑 |
| L4 | 人的感官结论 | 手感、可读性、是否好玩 |

硬口径（人 2026-10-25 明确）：

- **L3 只能算"证据的一部分"，不得称"全量 PASS"、不得作为交付完成依据。**
- L4 只能由人给；AI 不得用读数替代手感结论，也不得替人做"好不好玩"的判断。
- 门禁报告必须把 L3 的步骤点名列出（见 §5）。

## 5. 环境分层与 G6

| 场景 | 能力 | 谁负责重型步骤 |
|---|---|---|
| 受限会话（当前 DSH 沙箱） | 禁管道子进程；npm 可能解析到错误 shim | 只跑能跑的部分；报告标 L3 |
| 完整会话（人的终端） | 无管道限制 | 全量门禁、build、storybook、starter |
| 夜间任务 | 本机计划任务 | deep-audit、夜检摘要 |

- `tools/gate.mjs` 记录**环境指纹**（node 版本、平台、管道可用性）到报告；管道被禁时明确提示"依赖子进程的步骤未执行 ≠ 代码违规，但不计 PASS"。
- 不因此放宽任何阈值；**没有"警告通过"**。
- 环境本身坏掉（如 npm shim 指向未安装的 Node）视为需要修复的工具问题，按 §7 自动化修，不用人肉绕过。

## 6. 决策权与"人的在场"

- 人在场：**一切判断以人为准**，AI 不先斩后奏。
- 人不在场：仅**可逆** HARD（如门禁检查泛化、工具修复）可先做后报，并在 ADR 与 handoff 标注"待追认"；**不可逆**动作（发布、推送、删数据、改冻结契约、改仓库历史）一律停等。
- 方向校正由人决定；AI 只做评估与记录。
- 迭代是否完成由人验收；机器只能给"检查点全绿"。

## 7. 自动化优先

- 基础工作（状态检查、门禁、报告、截图、回执）必须由工具完成；**人肉纪律不是流程**。
- 新发现的重复劳动，优先变成检查/工具，而不是写进"注意事项"。
- 工具自身坏掉时**修工具**，不写"已知问题"绕过（例：`status.mjs` 的假信号、检查脚本的管道捕获）。

## 8. 收尾清单（每次迭代必做）

1. `node tools/gate.mjs`；把 `artifacts/gate/<run>/report.md` 摘要写进回复与交接。
2. 更新 `docs/交接.md`（本轮完成 / 下一步 / 待人裁定 / 环境说明）。
3. 更新 `docs/质量日志.md` 一行。
4. 补迭代记录与受影响系统卡 / ADR。
5. Git：功能级或迭代级 commit；迭代验收通过打 `iter/NNN`；可玩里程碑打 `milestone/<name>`；方向校正打 `pivot/YYYY-MM-DD`。
6. 交付：`node tools/flow.mjs ship`（门禁 → receipt → 按需深检 → ff-only 合并 → 推送 → 删除已合并分支）；网络失败见 `docs/runbooks/04-推送与网络策略.md`，分支清理见 `docs/runbooks/05-分支生命周期.md`。失败先分"策略"还是"网络"，原文记入 handoff。

## 9. 发布线（当前状态）

- npm `agent-specific_ecs@0.1.0` 已 staged，账号因恢复码冻结至约 2026-10-28 00:34 +08；**解冻前只做本地质量**。
- 解冻后由人交互发布（passkey）或 TOTP approve；首包后配置 OIDC trusted publishing；GitHub Actions 夜检在首包后再接。
- 引擎包体只允许 `dist/src` + `docs`（中英）+ `README.md`；游戏与夹具永远不进包体（`contracts/export-policy.json` 与 `package-surface` 门禁保证）。

## 10. 停止条件

- 目标完成且人验收 → 记录、tag、结束。
- 同一检查点 3 轮修复不过 → 上报。
- 触碰边界约束或超出文件范围 → 立即停止并上报。
- 需要方向校正 → 暂停，交人评估。
- 人说停 → 停。
