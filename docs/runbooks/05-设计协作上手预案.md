# 05 · 设计协作上手预案（未来场景，当前无常态设计角色）

> 定位：本项目是**个人项目**，当前没有常驻设计师参与。本文是**未来可能合作**时的上手预案，用来验证「零工程环境评审」这条路是否成立；现阶段可只作为自检清单使用。

目标：协作方用**任意顺手的工具**出稿与标注（免费版 Figma、截图、手绘都行），以 **Storybook** 的真实渲染为唯一验收面；不需要 Node / Docker / 数据库，也不需要付费席位。

## 你需要的

- 浏览器
- 一个能打开静态页面的环境（本地文件服务或内网地址）
- 可选：免费版 Figma（只当草稿/标注工具，不接 Dev Mode）

**不需要**：Node、Bun、Docker、Supabase、Figma 付费席位。

## 评审入口

开发会给你两种之一：

1. 本地服务：`http://localhost:6006`（开发跑 `npm run storybook`）
2. 静态包：`ui-kit-storybook.zip`，解压后由开发跑 `npm run storybook:serve`，打开 `http://localhost:7007`

里面有两个入口：

- **战斗 HUD / 控制条**：就绪 / 有诊断 / 存档失败 三个状态
- **设计 token / 总览**：颜色、字号、间距、圆角的真实值

## 组件与设计稿的对应关系

| 设计稿里的元素 | 代码里的组件 | Storybook 故事 |
|---|---|---|
| 顶部控制条（存档/读档/清除/导出/导出诊断） | `App` 的按钮组 | 战斗 HUD / 控制条 → 就绪 |
| 状态文字（`已存档 @ tick …`） | `App` 的 note 区 | 同上（有诊断 / 存档失败） |
| 数值行（tick/实体/弹/击杀/刚体） | `App` 的统计行 | 同上 |
| 颜色/字号/间距 | `tokens.ts` | 设计 token / 总览 |
| 战场（方块、弹道、玩家机） | Pixi canvas，不在本轮设计范围 | 无 |

## 修改流程（四步）

1. **出稿/标注**：任意工具，写清「组件名 + 状态 + 期望值」（颜色可给十六进制，间距给 4 的倍数）。
2. **对照真实渲染**：打开 Storybook 对应故事，和自己的稿并排比。
3. **提差异**：一句话说清「哪里、期望什么、为什么」，例如：
   - 「存档按钮 hover 底色期望 `#292524`（现在是 `#1c1917`）」
   - 「数值行在 1280 宽时换行了，期望单行」
4. **复查**：开发改完会更新 story，你再看一遍。

## token 速查（与 `tokens.ts` 一致）

| 用途 | 值 |
|---|---|
| 页面底色 | `#111111` |
| 正文 / 次要 / 弱化 | `#e7e5e4` / `#a8a29e` / `#78716c` |
| 按钮底 / 边 / hover | `#1c1917` / `#44403c` / `#292524` |
| 强调色（谨慎使用） | `#fb923c` |
| 字号 | 控制条 13px、统计行 12px |
| 间距 | 4 的倍数；gap 8px；内边距 10×5 |
| 圆角 | 6px |
| 字体 | 等宽 |

新增 token 需要先改 `tokens.ts` 与 `docs/UI最终方案.md`，再改组件与故事。

## 边界

- 战场内的单位、弹道、特效由 Pixi 画，**设计稿不直接生成这些**。
- 控制条的 DOM 结构尽量少改；改结构会同时影响故事与可访问性。
- hover/disabled/空状态请在标注里写全，开发按状态各建一个 story。
- 不引入任何云端服务或付费席位作为评审前提。
