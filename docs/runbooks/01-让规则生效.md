# Runbook 01 · 让规则生效（从零到可验证）

> 适用：全新终端、或换机器后第一次开工。
> 每一步都给「目的」与「预期输出」。输出对不上就停，按文末排查表处理。

---

## 0. 前置：确认工具链

```powershell
cd "E:\个人游戏项目\IntoTheBattlefiel深入战火"
node -v
npm -v
git --version
```

**目的**：确认 Node ≥ 22、npm、git 可用（Vite 8 与 `node:test` 都要求 Node 22+）。
**预期输出**：

```
v24.14.0
11.9.0
git version 2.47.1.windows.1
```

---

## 1. 安装依赖（仅首次或换机器）

```powershell
npm install --ignore-scripts --cache .npm-cache
```

**目的**：装依赖，且把 npm 缓存放在工作区内（本机沙箱不允许写用户目录缓存）。
`--ignore-scripts` 是因为 esbuild 的安装脚本会 spawn 子进程、在本机被拒绝；其二进制由可选依赖提供，不影响 Vite 8（Vite 8 用 rolldown，不用 esbuild）。
**预期输出**：`added N packages` 且退出码 0；目录下出现 `node_modules\`。

---

## 2. 装配钩子与目录

```powershell
node tools/setup.mjs
```

**目的**：把 git 钩子路径指向仓库内的 `.githooks/`（而不是不可版本化的 `.git/hooks/`），并建好 `artifacts/`、`.gate/stamps/`、`docs/adr/`。
**预期输出**：

```
Node      24.14.0
钩子路径  .githooks
下一步： …
```

---

## 3. 看当前状态（每次开工第一步）

```powershell
node tools/status.mjs
```

**目的**：不凭记忆开工——确认 HEAD、脏文件数、上次门禁结论与时间、stamp 数量。
**预期输出**（示例）：

```
HEAD      d6c1c2e
分支      main
脏文件    0
上次门禁  PASS  2026-10-20T14:29:56.xxxZ  artifacts/gate/20261020T142956Z
stamp 数  3
```

---

## 4. 跑全量门禁（规则真正生效的地方）

```powershell
node tools/gate.mjs
```

**目的**：按顺序执行 13 项检查——`tsc` 类型、`eslint` 规则与体积/复杂度、`registry` 自定义校验（含**端口冻结哈希**）、6 个测试文件、`gitfacts`（受保护路径与禁用标记）、`depcruise` 分层边界、`findings` 生成可定位诊断、`build` 验证 Vite 能出包。
**预期输出**：每行 PASS，最后两行是报告路径与 stamp：

```
tsc        PASS
eslint     PASS
registry   PASS
test-commands PASS
test-data PASS
test-demo.contract PASS
test-physics PASS
test-scheduler PASS
test-world PASS
tests      PASS（6 个文件）
gitfacts   PASS
depcruise  PASS
findings   PASS
build      PASS
报告：artifacts\gate\<时间戳>/report.md（PASS）
stamp 已写入 .gate/stamps/<HEAD>.json
```

**这一步通过 = 规则生效**：以后任何改动只要越界、超预算、改松阈值，都会在这里变红。

## 8. 记录一次批阅（把「批阅」也变成可审计事实）

```powershell
node tools/review.mjs accept --note "端口 v2 契约可接受"
```

**目的**：把结论与理由写进 `docs/review-log.md`，并打印下一步命令。
**预期输出**：

```
已记录：accept — 端口 v2 契约可接受
下一步（打标签前先确认全量门禁通过）：
  pnpm gate
  git tag -a v0.1.0-engine-core -m "<批次说明>"
  git push --follow-tags
```

---

## 9. 提交（钩子在这里证明自己是活的）

```powershell
git add -A
git commit -m "chore: 验证门禁与钩子"
```

**目的**：`pre-commit` 会自动执行快速门禁（`node tools/gate.mjs --fast`），失败即拒绝提交。
**预期输出**：先看到门禁的 PASS 行，再出现 `[main xxxxxxx] chore: 验证门禁与钩子`。

> 注意：在 DSH 沙箱内 git 的 `sh.exe` 无法启动，钩子不会执行，需要 `git commit --no-verify` 并手动跑第 4 步。在你自己的 Git Bash / PowerShell 终端里钩子正常生效。

## 排查表

| 现象 | 含义 | 处理 |
|---|---|---|
| `node : 无法将...识别` | Node 未装或不在 PATH | 安装 Node ≥ 22，重开终端 |
| `npm install` 报 EPERM / 缓存错误 | 缓存写到了工作区外 | 确保用了 `--cache .npm-cache` |
| `gate` 在 `registry` 失败并提示「端口契约已变化」 | 有人改了 `ports/index.ts` | 确认是 HARD 变更后：`node tools/checks/registry.mjs --accept-ports`，并补 ADR |
| `gate` 在 `gitfacts` 失败并列出 `tools/` 等路径 | 改了保护路径 | 确认是授权改动后：`$env:ALLOW_PROTECTED="1"; node tools/gate.mjs`，并补 ADR |
| `gate` 在 `build` 失败 | Vite 出包失败 | 看 `artifacts/gate/<run>/build.log` |
| `npx vite` 起不来（沙箱内） | 沙箱限制 | 在自己的终端跑；或只跑 `vite build` |
| 提交时钩子报 `sh.exe: couldn't create signal pipe` | 沙箱内 MSYS 不可用 | 用 `--no-verify` 提交，之后手动跑全量门禁 |
