# 05 · 设计师上手（不需要安装任何工程工具）

目标：设计方**不离开 Figma** 就能完成 UI 设计、对比真实渲染、提交修改，不需要 Bun / Docker / Node / 数据库。

## 你需要的

- 浏览器（看 Figma 与 Storybook）
- Figma 账号（沿用你现有的习惯）
- 可选：Figma 桌面版 + Dev Mode（看标注更顺）

**不需要**：装 Node、Bun、Docker、Supabase；不需要碰代码仓库。

## 组件与设计稿的对应关系

| 设计稿里的元素 | 代码里的组件 | Storybook 故事 |
|---|---|---|
| 顶部控制条（存档/读档/清除/导出/导出诊断） | `App` 的按钮组 | 战斗 HUD / 控制条 → 就绪 |
| 状态文字（`已存档 @ tick …`） | `App` 的 note 区 | 同上（有诊断 / 存档失败 两个状态） |
| 数值行（tick/实体/弹/击杀/刚体） | `App` 的统计行 | 同上 |
| 战场（方块、弹道、玩家机） | Pixi canvas，**不在本轮设计范围** | 无 |

组件源码位置：`apps/game/src/ui/App.tsx`；只读快照类型：`apps/game/src/ui/snapshot.ts`。

## 修改流程（四步）

1. **在 Figma 改稿**：保持组件命名与上表一致；新增元素请用「组件/状态」命名，例如 `Button/Primary`、`StatRow`。
2. **标注释**：间距用 4 的倍数，颜色尽量用现有色板（深底 `#111`、按钮底 `stone-900`、正文 `stone-200`、次要文字 `stone-400/500`），字号 13/12。
3. **对照真实渲染**：让开发起 Storybook（`npm run storybook`），打开 `http://localhost:6006`，把 Figma 与真实组件并排比对，列出差异。
4. **提交差异**：用一句话描述「哪里、期望什么、为什么」，例如：
   - 「存档按钮的 hover 底色比设计深一档，期望 `stone-800`」
   - 「数值行在 1280 宽时换行了，期望保持单行」

不需要提代码；开发会按 `UiSnapshot`/`UiIntents` 契约实现，并补 Storybook 状态。

## 设计 token（当前实现）

| 用途 | 值 |
|---|---|
| 页面底色 | `#111111`（Pixi 背景） |
| 控制条文字 | `stone-200` / 等宽字体 |
| 次要文字 | `stone-400`、`stone-500` |
| 按钮 | 底 `stone-900`、边 `stone-700`、圆角 6px、内边距 5×10 |
| 字号 | 控制条 13px、统计行 12px |

新增颜色/字号请先在这些值里选；确实需要新值，再和开发确认是否进 token 表。

## 边界（避免返工）

- 战场内的单位、弹道、特效由 Pixi 画，**Figma 稿不直接生成这些**；需要新战场表现请单独提需求。
- 控制条的 DOM 结构尽量少改；改结构会同时影响 Storybook 故事与可访问性。
- 交互态（hover/disabled）请在 Figma 里给全，开发按状态各建一个 story。
