# Runbook 02 · 提交审核流程

> 适用：每批交付、每次合并、每次打 tag 之前。
> 目标：让「批阅」本身成为可审计事实，而不是口头一句「可以了」。

---

## 1. 它解决什么问题

代码检查（`gate`）回答「能不能通过」，**审核**回答「该不该接受」。两者缺一：

- 只有 gate：AI 只要让检查变绿就能推进，没人对「这个方向对不对」负责。
- 只有审核：结论散落在聊天记录里，下一次会话无从追溯。

所以审核流程做三件事：

1. **强制写理由**：空理由会被脚本拒绝——「可以了」不是理由。
2. **落盘成事实**：每次 accept / reject 追加一行到 `docs/评审日志.md`（时间、结论、HEAD、理由）。
3. **给出下一步命令**：接受 → gate + tag；拒绝 → revert 或继续修。命令由面板生成，避免手敲出错。

---

## 2. 三条命令（手工方式）

```powershell
# 接受
node tools/review.mjs accept --note "端口 v2 契约可接受"

# 拒绝
node tools/review.mjs reject --note "渲染相机没居中，退回"

# 带标签的接受（打批次 tag）
node tools/review.mjs accept --note "第二批可交付" --tag v0.2.0-render-physics
```

**预期输出**：`已记录：accept — …`，随后打印下一步命令（accept：gate → tag；reject：修复或 revert）。

**影响（写到哪里）**：

| 产物 | 位置 | 作用 |
|---|---|---|
| 批阅记录 | `docs/评审日志.md` | 可审计的结论链，随提交进版本库 |
| 下一步命令 | 终端输出 | 不自动执行，由人复制 |

脚本**不会**自动提交、不会自动打 tag、不会自动 revert——它只记录并给建议。

---

## 3. 审核台（面板内生成脚本）

打开 `tools/panel/panel.html`，底部「批阅台」：

1. 选结论（accept / reject）；
2. 填理由（必填）、标签（可选）、目标提交（reject 时用于 revert）；
3. 面板即时生成 **PowerShell** 与 **CMD** 两段脚本；
4. 点「复制」或「下载」。

参数变了脚本就变，规则不变：**面板只生成、不执行**，避免在 Git 之外长出第二份事实。

---

## 4. 与 gate 的关系

```
改代码 → node tools/gate.mjs（能不能过）→ 人批阅 → accept/reject（该不该收）
                                          ↓
                                    gate 复跑 + tag / revert
```

- 批阅**不替代** gate：accept 之后仍要跑全量门禁并打 tag。
- gate **不替代**批阅：全绿只说明检查通过，不说明方向正确。
- 当前全量门禁 30+ 步，除类型/规则/测试外，还包括 `replay`（三次一致）、`depcruise`（解析 violations）、`drill`（违规演练）、`storybook` / `starter`（画布构建）、`bench`（逻辑帧基线）。`--fast` 会跳过 `gitfacts`、`depcruise`、`drill`，只用于中途自检。

---

## 5. 拒绝之后怎么走

| 情况 | 做法 |
|---|---|
| 还能在原分支修 | 直接修 → 重新 gate → 重新批阅 |
| 该提交本身不合规 | `git revert <sha>` → 重新 gate → 批阅 |
| 整批方向错了 | 停在该分支，不合并；批次作废需写 ADR |

---

## 6. 常见误用

- 用「可以了」「没问题」当理由 → 脚本不拦文本内容，但记录会失去价值；理由要写**判断依据**。
- 批阅后不跑 gate 就打 tag → tag 指向未验证提交，回滚时无从判断。
- 把面板当写操作台 → 面板只生成脚本，执行永远在终端。
