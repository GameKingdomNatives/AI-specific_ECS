# 05 · 分支生命周期（自动化入口）

> 口径：人不需要记分支命令；AI 与人都只调用 `node tools/flow.mjs`。

## 四条命令

```bash
node tools/flow.mjs status    # 每个分支：合并状态 / 年龄 / 是否有 stamp
node tools/flow.mjs policy    # 策略是否满足（HEAD 的 stamp+receipt；过期未合并分支）
node tools/flow.mjs sweep     # 删除已合并本地分支（--remote 同时尝试删远端）
node tools/flow.mjs ship      # 交付：门禁 → receipt → 按需深检 → 合并 → 推送 → 删分支
```

## 什么时候建分支

| 场景 | 做法 |
|---|---|
| 单个迭代、<= 若干提交、可随时重跑门禁 | 直接在 main 上提交，`ship` 推送 |
| 大改动 / 需要并行试验 / 可能回滚 | 建分支；`ship` 会自动 ff-only 合并并删除 |
| 一次性工程文件（探针、临时脚本） | **不建分支**；放进 `artifacts/` 或临时目录（已 gitignore） |

## 推送判定（新）

`pre-push` 不再按分支名拦截 main；它对**每个被推送的 tip** 校验 `gate stamp`，对 HEAD 校验 receipt 与深检节奏。

- 失败类型只有两种：**证据不足**（跑 `flow ship`）或**网络不通**（见 runbook 04）。
- 没有 `--no-verify` 这一说：绕过本地钩子不会造出 stamp。

## 清理规则

- `sweep` 只删 `merge-base --is-ancestor <branch> main` 为真的分支；未合并分支只报告。
- 已合并但领先自己 upstream 的分支，会在确认合并后用 `-D` 删除（唯一合法的强删场景，理由写在此处）。
- 远端分支删除需要网络；失败会保留并打印原因，下次再 sweep。
