# Runbook 04 · UI 组件画布与设计评审（Storybook）

> 用途：本地起组件画布、把组件状态摆出来评审、导出静态包交给别人看。
> 本项目的设计协作是**未来场景**（当前为个人项目，无常态设计角色）；本文同时作为自检清单使用。

## 0. 先分清两件事

| 目标 | 工具 | 能看/能改什么 |
|---|---|---|
| 看组件在每种状态下的真实渲染 | Storybook | `apps/game/src/ui/**` 的 React 组件 |
| 交给别人看（不装任何工具） | 静态构建 | 同一批组件的静态网页 |
| 战场画面（方块、弹道、玩家机） | Pixi canvas | **不在 Storybook 覆盖范围** |

Storybook 是**组件陈列与验收面**，不是代码编辑器：它展示真实渲染，不写回源码。

## 1. 本地跑起来

```powershell
npm run storybook          # http://localhost:6006
npm run storybook:build    # 静态包 → artifacts/storybook-static
npm run storybook:serve    # 静态包 → http://localhost:7007
```

只验证 UI 时不需要 `npm run dev`（游戏主循环）；Storybook 单独渲染组件。

发给别人（对方零安装）：

```powershell
Compress-Archive -Path artifacts\storybook-static\* -DestinationPath artifacts\ui-kit-storybook.zip -Force
```

## 2. 现在有哪些故事

**主应用**（`apps/game/src/ui/`）：

| 标题 | 故事 |
|---|---|
| 战斗 HUD/控制条 | 就绪 / 有诊断 / 存档失败 |
| 设计 token/总览 | 颜色、字号、间距、圆角 |

**独立起步工程**（`starters/ui-storybook-kit/`，可单独复制）：

| 标题 | 故事 |
|---|---|
| 基础组件/按钮 | 默认 / 主色 / 禁用 |
| 基础组件/状态文字 | 普通 / 弱化 / 报错 |
| 基础组件/信息行 | 有数据 / 空数据 |
| 设计/颜色与尺寸 | 总览 |

全量门禁里的 `storybook` 与 `starter` 步骤分别构建这两套，防止它们腐烂。

## 3. 评审流程（协作方零工程环境）

1. 开发构建静态包（或起 `:6006`）；
2. 评审方用任意工具出稿/标注（免费版 Figma、截图、手绘均可），对照 Storybook 的真实渲染；
3. 按「哪里、期望、为什么」提差异，例如「存档按钮 hover 期望 `#292524`」「数值行在 1280 宽换行了」；
4. 开发改组件与 story，重新构建静态包；
5. 改动走 `node tools/gate.mjs` 后提交。

不需要 Node / Docker / 数据库 / 付费席位。

## 4. 为什么没有 Onlook

我们完整评估过 Onlook（自托管与桌面版），结论是**排除**：

- 自托管要 Bun + Supabase CLI + Docker + 数据库迁移，在 Windows 上不可稳定复现；
- 旧版 CLI 拒绝全局安装，npm 安装时下载二进制又受网络影响；
- 上游配置与源码不一致（声明了仓库不存在的函数），迁移又撞上新版 Storage 限制；
- 稳定产物只有 2025-07 的桌面版，能否打开本地项目未验证。

完整时间线与代价见 [`docs/lessons/经验教训-·-2026-10-UI-工具链.md`](../lessons/经验教训-·-2026-10-UI-工具链.md)，面向新人的评估记录见
[`starters/ui-storybook-kit/docs/00-为什么不用-Onlook.md`](../../starters/ui-storybook-kit/docs/00-为什么不用-Onlook.md)。

## 5. Figma 的角色

Figma（或任何设计稿工具）**仅作可选草稿/标注**，免费版足够；不接 Dev Mode、不接 MCP、不需要付费席位。
两类工具的对应关系见 [`starters/ui-storybook-kit/docs/01-Storybook-与-Figma.md`](../../starters/ui-storybook-kit/docs/01-Storybook-与-Figma.md)。

## 6. 新增或修改组件

1. 组件放 `apps/game/src/ui/`，只接受纯数据与回调；
2. 同目录建 `Xxx.stories.tsx`，至少三个状态（默认 / 边界 / 禁用）；
3. token 唯一事实源是 `apps/game/src/ui/tokens.ts`，新增先改它与 `docs/UI最终方案.md`；
4. `node tools/gate.mjs` 通过后提交，并重新构建静态包；
5. UI 目录禁止 import `packages/**` 或应用控制器（depcruise 规则 `ui-no-engine-internals` 会拦）。

## 7. 排错

| 现象 | 处理 |
|---|---|
| `storybook` 起不来 | 确认 `storybook` 与 `@storybook/react-vite` 均为 10.6.x（peer 含 `vite ^8`） |
| 改 `vite.config.ts` 后样式没变 | 重启 dev server / Storybook |
| 静态包白屏 | 用 `npm run storybook:serve`，不要 `file://` 直开 |
| 门禁报 `ui-no-engine-internals` | UI 里 import 了引擎/控制器，改为经 props 传入 |

## 8. 许可证

Storybook、React、Tailwind、Vite 均为 **MIT**，可免费商用；评审链路不含任何付费服务。
