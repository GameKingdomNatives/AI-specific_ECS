# Runbook 03 · 回放与偏离定位

> 用途：确认「同一个录制重演两次结果一致」；出现不一致时，直接定位到第一个偏离的 tick。

## 1. 自测（不需要任何文件）

```powershell
node tools/replay.mjs --self-test
```

**目的**：生成 30 个 tick 的输入，默认连续重演三次，比对逐 tick 哈希；`--repeat 5` 可改次数。
**预期输出**：

```
ticks      30
runs       3
final      5a66a27c
重复 3 次一致   PASS
```

## 2. 写一份录制文件

```powershell
node tools/replay.mjs --write artifacts\replay-demo.json --ticks 30
```

**目的**：产出一份可版本化的录制（纯文本 JSON，键顺序固定，可直接 diff）。
**预期**：`已写入 artifacts\replay-demo.json（30 ticks）`。

## 3. 回放并查看哈希

```powershell
node tools/replay.mjs artifacts\replay-demo.json
```

**预期输出**：

```
ticks      30
final      5a66a27c
first      b7ea227c
```

`final` 必须与自测一致（同一录制 = 同一世界）。

## 4. 与历史对比（CI 回归方式）

```powershell
# 把某次的哈希序列存成文件：{"hashes":["b7ea227c", "..."]}
node tools/replay.mjs artifacts\replay-demo.json --expect artifacts\replay-demo.hashes.json
```

**预期**：`哈希对比   PASS`；若不一致，输出 `首个偏离   tick N`——N 就是回归定位点，配合录制里的输入可以直接复现。

## 4.5 重演浏览器里的那一局

```js
// 页面控制台：取录制与当前哈希
__itb.recording()   // JSON 文本，可存成文件
__itb.hash()        // 当前最终哈希
```

```powershell
node tools/replay.mjs --app <录制文件> --expect-hash <页面上的哈希>
```

**预期**：`final` 与 `哈希对比 PASS`。实测：一局 386 tick、含射击与命中（击杀 1）的录制，两侧哈希一致。

**哈希口径**：浏览器与 CLI 都按分组计算——`[[Position, Box], [Position, Bullet]]`。原因是方块与子弹的组件互斥，单次 `worldHash` 会得到空集（详见 ADR-005）。

**前提**：录制必须来自「干净开局」。内容热加载（改 `demo.boxes.json`）会重建方块实体，跨热加载的录制与开局重演不是同一个世界——这类录制不应参与哈希回归。录制里带 `startHash`，CLI 会在重演前比对；不一致会明确报「干净开局 不匹配」并拒绝。

## 5. 它不做什么

- 不启动浏览器、不渲染、不依赖实时帧率；
- 不替你判断「这个差异是好是坏」——那属于批阅；
- 不自动修复：只报「第几个 tick 开始不一致」。

## 6. 现在覆盖到哪里

- 门禁里的 `replay` 步骤：`--self-test --repeat 3`，三次全哈希序列比对；
- 浏览器端：完整战斗世界（方块、子弹、刚体同步、命中、回收）可导出录制，CLI `--app` 重演并能通过 `--expect-hash` 比对；
- 尚未覆盖：事件记录（EventBus 的 record）未参与重演；跨内容热加载的录制按设计拒绝。
