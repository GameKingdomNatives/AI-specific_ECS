# Runbook 03 · 回放与偏离定位

> 用途：确认「同一个录制重演两次结果一致」；出现不一致时，直接定位到第一个偏离的 tick。

## 1. 自测（不需要任何文件）

```powershell
node tools/replay.mjs --self-test
```

**目的**：生成 30 个 tick 的输入，连续重演两次，比对逐 tick 哈希。
**预期输出**：

```
ticks      30
final      5a66a27c
重演一致   PASS
```

## 2. 写一份录制文件

```powershell
node tools/replay.mjs --write artifacts\replay-demo.json --ticks 30
```

**目的**：产出一份可版本化的录制（纯文本 JSON，键顺序固定，可直接 diff）。
**预期**：`已写入 artifacts\replay-demo.json（30 ticks）`。

## 3. 回放并查看哈希

```powershell
node tools/replay.mjs artifacts\replay-demo.json
```

**预期输出**：

```
ticks      30
final      5a66a27c
first      b7ea227c
```

`final` 必须与自测一致（同一录制 = 同一世界）。

## 4. 与历史对比（CI 回归方式）

```powershell
# 把某次的哈希序列存成文件：{"hashes":["b7ea227c", "..."]}
node tools/replay.mjs artifacts\replay-demo.json --expect artifacts\replay-demo.hashes.json
```

**预期**：`哈希对比   PASS`；若不一致，输出 `首个偏离   tick N`——N 就是回归定位点，配合录制里的输入可以直接复现。

## 5. 它不做什么

- 不启动浏览器、不渲染、不依赖实时帧率；
- 不替你判断「这个差异是好是坏」——那属于批阅；
- 不自动修复：只报「第几个 tick 开始不一致」。

## 6. 现在覆盖到哪里

当前 CLI 用的是一个最小场景（一个实体按输入位移）来验证回放机制本身。等 60Hz 主循环接入真实输入端口后，回放对象会换成完整的战斗世界，用法不变。
