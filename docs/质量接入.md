# Quality adoption · 把质控方案装进你的仓库

> 状态：规划（npm 首包后随 v0.2.0 落地）。设计见 `docs/proposals/007-一条命令把质控方案装进别人的仓库.md`。

## 一条命令

```bash
npx agent-specific_ecs-quality init
```

它会把本仓库在用的质控策略（门禁、回执、stamp 链、本地分支保护、保护路径、禁用标记扫描、测试基线）写进你的仓库，并设置 `core.hooksPath`。

## 装完你的仓库会多出什么

| 路径 | 作用 |
|---|---|
| `quality/gate.mjs` | 通用门禁入口；配置驱动，不写死路径 |
| `quality/checks/` | 受保护路径 / 禁用标记 / 测试基线 / 依赖边界 |
| `quality/receipt.mjs` | 交付回执（HEAD、tree、命中规则、结果） |
| `quality/stamp.mjs` | 门禁通过后写 stamp，供 pre-push 校验 |
| `.githooks/pre-commit` | 快速门禁（≤20s） |
| `.githooks/pre-push` | 全量门禁 + stamp 链（本地分支保护） |
| `quality.config.json` | **你唯一需要改的文件**：路径与阈值 |
| `docs/quality/README.md` | 上面这些文件的索引与排查手册 |

## 边界

- 不写业务代码；不碰 `apps/`；不装游戏内容。
- 允许 `--no-verify`，但推送时 stamp 链会拒绝未验证的提交——检测并拒绝交付，不假装物理禁止。
- 环境受限（如禁止管道子进程）导致某步未执行时，报告标 L3，**不计 PASS**。
